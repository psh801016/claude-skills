# 도면 → 캐드(DXF) → 3D

2D 도면에서 **캐드 베이스 도면(DXF)**과 **3D 모델(.blend)**을 만든다.
엔진 = Python(판독·작도) + **Blender 5.1 headless**(압출·렌더).
ASURA의 **CGI→AI 실사화** 파이프라인 입력 자산을 만드는 핵심·반복 작업이다.

## 이 스킬의 제1원칙 — AI에게 선을 긋게 하지 마라

가장 흔한 실패는 "AI야 이 도면 보고 캐드 그려줘"다. 결과가 항상 엉망인 이유는 셋이다.

1. **AI는 자가 없다.** 이미지에서 픽셀을 정확히 재지 못한다. 3,600mm 벽을 3,480으로 쓴다.
2. **DXF를 글자로 쓰게 하면 중간에 흐트러진다.** 벽 20개면 수천 줄이고, 후반부터 형식이 깨진다.
3. **축척을 안 정하고 시작하면** 비율만 맞고 크기가 통째로 틀린다. 그런데 **보기엔 멀쩡해서** 아무도 못 잡는다.

그래서 이 스킬은 역할을 자른다. **AI는 도면을 '읽어서 숫자표(JSON)'만 채우고, 선은 결정론적
스크립트가 긋는다.** 이 분리가 품질의 대부분을 만든다. 판독 결과는 그림을 그리기 **전에**
검산기가 잡아낸다 — 틀린 걸 그려놓고 눈으로 찾는 것보다 훨씬 싸다.

## 제2원칙 — 보지 않은 화면을 설명하지 마라

렌더를 띄웠으면 **반드시 `Read`로 직접 보고** 말하라. 안 보고 "잘 나왔습니다"라고 쓰는 순간
틀린 걸 납품하게 된다. 오늘까지 잡힌 버그(mm→m 누락·노출 과다·프레임 잘림)는 **전부 눈으로
봐야만 보이는 것**이었다 — 로그는 셋 다 정상이라고 말하고 있었다.

같은 이유로 경로 B는 `preview.png`, 경로 C는 `overlay.png`를 먼저 보고 넘어간다.

## 입력 유형 판별 — 여기서 품질이 갈린다

도면 문법(선 종류·레이어 표준·기호)은 `references/건축도면_이해_체계.md` 참고.

```
입력이 무엇인가?
├─ DWG / DXF 원본                  → 경로 A. 좌표가 실제로 있다. 최정밀.
├─ 치수가 인쇄된 도면 이미지/PDF     → 경로 E ★권장. 숫자를 읽으면 픽셀 측정이 필요 없다.
├─ 치수 없는 벡터 PDF               → 경로 B. 평행선쌍 → 중심선.
└─ 치수 없는 래스터(스샷/사진)       → 경로 C. 픽셀 추출 + 제원표로 축척.
```

**게이트 — PDF/이미지가 오면 원본 DWG/DXF가 있는지 먼저 1회 확인한다.** PDF는 레이어 평탄화로
벽/문/창 분류가 이미 지워졌고 래스터는 더하다. 사용자가 "없다/모른다"면 그때 진행한다.
(무인·자동화 맥락이면 묻지 말고 진행하되 보고에 "원본 DWG 미확인" 명시.)

**조용한 킬러 = 축척.** 틀려도 결과가 그럴듯해서 놓치기 쉽다. 근거 없이 픽셀로 추정하지 마라.

빌드는 두 갈래다:

| 소스 | 빌더 | 결과 |
|---|---|---|
| `plan.json` (경로 E) | **경로 F** ★권장 | 바닥·인방·문짝·유리·장비·재질·레이어 포함 **모델** |
| `walls.json` / `rooms.json` (A·B·C) | 경로 D | 벽만 선 **매스 덩어리** (빠른 검토용) |

## 경로 E — 치수가 적힌 도면 이미지 → plan.json → DXF ★주력

사진이 비뚤어져 있어도 상관없다. **인쇄된 숫자를 읽지 픽셀을 재지 않기 때문이다.**
건축도면·시공도면·행사장 배치도처럼 치수선이 있는 도면이면 이 경로가 가장 정확하다.

### E-1. 판독 — AI가 JSON을 채운다

`references/plan-json-판독-프롬프트.md` 를 그대로 프롬프트로 쓴다(도면 이미지 첨부).
축척 확정 우선순위가 그 안에 박혀 있다: **① 치수선 → ② 면적 역산 → ③ 문 900mm 가정**.
③으로 갔으면 `meta.scale_ref`에 가정이라고 반드시 남긴다 — 나중에 이 도면을 믿을지 판단할 근거다.

확신 없는 부분은 **지어내지 말고** `meta.uncertain[]`에 한 줄씩 적는다. 여기 적힌 것이
사용자 보고의 "추정한 것" 항목이 된다. 근사한 부분을 정확한 척 넘기면 신뢰가 무너진다.

**스키마 요약** (전문은 references, 실제 예시는 `examples/venue-crystal-plan.json`·`apartment-84A-plan.json`):
```json
{
  "meta":     {"unit":"mm", "exclusive_area_m2":84.97, "scale_ref":"...", "uncertain":["..."]},
  "walls":    [{"a":[0,0],"b":[11400,0],"t":200,"type":"ext","h":5.4}],
  "openings": [{"wall":0,"at":1200,"w":900,"kind":"door","hinge":"a","swing":"in"}],
  "rooms":    [{"name":"거실","poly":[[100,100],[3200,100],[3200,4100],[100,4100]]}],
  "blocks":   [{"name":"STAGE 9.6x3.6","rect":[9200,22300,9600,3600],"h":0.6,"z":0}],
  "marks":    [{"label":"X배너(왼)","at":[29300,19800],"dir":"down"}],
  "routes":   [{"name":"동선1","pts":[[37000,2000],[36000,12000]]}]
}
```
- `walls` 는 **중심선**(양면 아님), 단위 mm, 원점은 좌하단. `h` 는 층고(m) — 실마다 다르면 벽마다 준다.
- `blocks` = 스테이지·LED·데스크·포토월 같은 장비. **행사장에선 이게 본체다** — 빼면 빈 상자만 남는다.
- `marks`/`routes` = 원도의 빨간 펜 표기(배너 위치·동선). **지우지 말고 별도 레이어로 살린다.**

### E-2. 검산 — 그리기 전에 잡는다

```bash
python scripts/plan2dxf.py plan.json --check
```
| 검사 | 걸리면 | 뜻 |
|---|---|---|
| 실면적 합 vs 전용면적 | 20%↑ 차이 → **중단** | 축척(px→mm)이 틀렸다 |
| 개구부가 벽 안에 있나 | 벗어나면 → **중단** | 좌표를 잘못 읽었다 |
| 벽이 직각인가 | 0.5°↑ → 경고 | 사선벽이 아니면 오독 |
| 벽두께 60~500 / 문폭 600~2400 | 벗어나면 → 경고 | 실무 범위 밖 |
| **개구부 자리에 직교벽이 서 있나** | 있으면 → **중단** | 그 폭으로 안 열린다. 3D 로 세워야 보이는 결함이라 여기서 잡는다 |

오류 문장이 나오면 **그 문장을 그대로 판독 AI에게 되돌려주고** JSON을 고치게 한다.
보통 한두 번 왕복이면 통과한다.

> 실면적 합은 전용면적보다 **5~12% 작은 게 정상**이다(벽 두께가 빠지므로). 이걸 모르면
> 멀쩡한 도면을 틀렸다고 착각한다.

### E-3. DXF 출력

```bash
python scripts/plan2dxf.py plan.json -o 도면.dxf
```
단위 mm, 1:1 실척. 레이어 분리: `A-WALL / A-WALL-C / A-DOOR / A-WIND / A-ROOM / A-AREA / A-EQPT / A-MARK / A-PATH`.
한글 실명은 `malgun.ttf` 스타일로 넣는다(기본 txt.shx는 한글이 깨진다).

벽 모서리는 사각형이 겹쳐 나온다. 캐드에서 TRIM 몇 번이면 정리된다 — 자동 정리 코드값이
그 클릭값보다 비싸서 일부러 안 넣었다.

## 경로 F — plan.json → Blender 3D 풀빌드 ★주력

```bash
"/c/Program Files/Blender Foundation/Blender 5.1/blender.exe" --background \
  --python scripts/build3d.py -- <plan.json> <출력폴더>
# → model.fbx / model.obj  ← 본 산출물 (3ds Max·SketchUp 으로 가져갈 것)
#   render_iso.png / render_top.png (2560x1440)  ← 검토용
#   model.blend / proof-log.json
```

**본체는 `.blend` 다. 이 스킬의 일은 블렌더 안에서 모델을 제대로 세우는 것까지다.**
FBX·OBJ 는 다른 툴로 옮길 때를 위해 같이 떨어뜨려 둘 뿐이고, **옮기는 일은 이 스킬의 범위가 아니다.**
(ASURA 지시 2026-09-15 — 타 프로그램 인계는 본인이 직접 한다.) 내보내기 옵션을 손보거나
임포트 방법을 설명하느라 시간 쓰지 마라. **모델 품질에 쓰라.**

참고만: 축은 Blender(Z-up) = 3ds Max(Z-up) 이라 변환이 없고, 오브젝트 이름이 그대로 레이어로 넘어간다.

경로 D와 달리 이것들이 들어간다. **하나라도 빠지면 "모델"이 아니라 "덩어리"로 보인다:**

- **바닥 슬래브** (실별) — 없으면 실이 눈으로 구분되지 않는다
- **문 위 인방 / 창대·창 상부벽** — 없으면 개구부가 천장까지 뚫린 구멍이 된다
- **문짝(90° 열림) · 유리(반투명)**
- **장비·가구** — `blocks`를 높이대로 세운다
- **재질 팔레트 + EEVEE + AgX 톤매핑 + 조명 3점**
- **레이어(컬렉션) 15종** — `camera / ceiling / ceiling_mesh / equipment / fix_furniture /
  floor / furniture / glazing / graphics / lighting_fixtures / lights / props / wall /
  wall_door / wall_finish`. 비어 있어도 만들어 둬서 다음 사람이 어디에 뭘 넣을지 알게 한다.

천장은 **일부러 안 만든다** — 아이소·탑뷰에서 내부가 전부 가려진다(돌하우스 방식).

### 재질·조명 프로파일 (`data/profiles.json`)

> **Max 로 가져갈 거면 이 절은 건너뛰어도 된다.** 재질·조명은 거기서 다시 잡는다.
> 프로파일은 **검토용 렌더를 읽기 쉽게 만드는 용도**이지 납품 재질이 아니다.
> 다만 실을 색으로 구분해 두면 반복 루프에서 오류를 훨씬 빨리 잡는다.

재질·조명 기본값은 코드가 아니라 **데이터**에 있다. 현장 종류가 바뀔 때 스크립트를 고치지 않는다.
`plan.json` 의 `meta` 에서 고른다:

```json
"meta": { "profile": "hotel_banquet", "lighting": "banquet_warm" }
```

| `profile` (재질) | 쓰는 곳 |
|---|---|
| `neutral` | 기본. 색을 안 정했을 때·구조 검토·실사화 i2i 입력 |
| `hotel_banquet` | 호텔 연회장·그랜드볼룸 (버건디 카펫 + 크림 벽 + 금색) |
| `exhibition` | 전시장·컨벤션 부스 (회색 파이텍스 + 화이트 부스 + 옥타늄 실버) |
| `apartment` | 주거 (강마루 + 오프화이트 도배) |

| `lighting` (조명) | 쓰는 곳 |
|---|---|
| `studio_neutral` | 기본. 색을 안 섞어 형태·배치가 가장 잘 읽힌다 |
| `banquet_warm` | 연회장 야간, 샹들리에 3000K |
| `exhibition_bright` | 전시장 주간, 메탈할라이드 4000K |
| `daylight` | 주광 6500K, 창 큰 공간 |

**우선순위: `plan["materials"]`(사진에서 뽑은 색) > `meta.profile` > `neutral`.**
현장 종류가 늘면 `profiles.json` 에 항목만 추가한다 — 코드는 안 건드린다.

### 완성 사진이 있으면 (선택)

도면은 **배치**를 주고 사진은 **재질·색·분위기**를 준다. 사진이 있으면 그 색을 읽어
`plan["materials"]`로 기본 팔레트를 덮어쓴다. 없으면 무채색 기본값으로 나온다 — **사진은 없어도 된다.**

```json
"materials": { "floor": {"rgb":[0.35,0.06,0.08]}, "wall": {"rgb":[0.93,0.93,0.91]} }
```
키: `wall floor stage led banner wood photo metal door glass props`.
각 키는 `rgb`(0~1) 외에 `rough` `metal` `emit` `alpha`를 받는다.

## ★ 반복 루프 — 한 번에 맞히려 하지 마라

이게 품질의 나머지 절반이다. 빌드는 몇 초면 끝나므로 **돌리고 → 보고 → 고치고 → 다시 돌린다.**

1. `build3d.py` 실행
2. **`render_iso.png`를 Read로 직접 본다** (이 단계를 건너뛰면 틀린 걸 납품하게 된다)
3. 아래를 눈으로 대조하고 고친다
4. 통과할 때까지 2~3으로 돌아간다

### 지오메트리 검사 — 눈으로 안 보이는 결함용

렌더로는 절대 안 보이지만 모델을 망치는 것들이 있다. 빌드 후 돌려라.

```bash
blender --background --python scripts/check_openings.py -- <model.blend> <plan.json>
```
문·창이 **설계 치수대로 실제로 뚫렸는지** 메시에서 직접 잰다(±60mm). 종료코드 1 이면 어긋난 것이다.
2026-09-15 이 검사로 잡은 것: 모든 벽 조각을 양끝 `t/2` 늘리는 바람에 **900mm 문이 (900−벽두께)mm
로 좁아져 있었다.** 지금은 **벽끼리 만나는 코너만** 늘린다.

> 측정할 때 **벽과 평행한 방향으로 레이를 쏘지 마라** — 판정이 불안정하다.
> 같은 날 이 실수로 멀쩡한 개구부를 NG 로 오판했다. 반드시 벽에 **수직**으로 쏜다.

**손대지 말아야 할 두 가지** (둘 다 측정으로 확인됨):
- `mesh.intersect_boolean(use_self=True)` 로 벽을 합치지 마라 → 비매니폴드 엣지 **0개 → 582개**.
- `remove_doubles` 를 벽에 걸지 마라 → 맞붙은 박스를 용접해 한 엣지에 면 4장이 모인다(**0 → 33개**).
  같은 좌표에 정점이 겹쳐 보여도 **박스마다 닫힌 솔리드인 현 상태가 정상**이다.

정리 패스가 남기는 것: 노멀 일관성 + **Smart UV 전개**(없으면 재질 작업을 못 한다).

**매 루프 점검표** — 실제로 이 순서로 버그가 잡혔다:

| 증상 | 원인 | 조치 |
|---|---|---|
| 건물이 수만 m로 나옴 | mm→m 변환 누락 | 좌표에 `×0.001` |
| 전부 하얗게 날아감 | 노출·필광 과다 | `exposure`↓, area light energy↓ |
| 위/아래가 잘림 | `ortho_scale`은 **가로에만** 걸린다 | 세로에 화면비를 곱해 fit |
| 바닥이 벽과 구분 안 됨 | 알베도가 너무 비슷 | floor를 확실히 어둡게 |
| 문이 천장까지 뚫림 | 평면 절단만 하고 높이를 안 채움 | 인방/창대 세그먼트 추가 |
| 방이 텅 빔 | `blocks` 누락 | 장비를 JSON에 넣는다 |
| 문이 설계보다 좁음 | 문선(jamb)까지 `t/2` 연장 | 코너에서만 연장 (`JUNC` 판정) |
| 문이 안 열림 | 그 자리에 직교벽이 서 있음 | 검산에서 중단됨 — 도면을 다시 읽어라 |

**전달물은 `.blend` + 렌더 PNG 다.** 숫자(오브젝트·면 수·건물 치수)를 같이 적어야 받는 쪽이 검증할 수 있다.

## 경로 A — DWG / DXF 원본 (좌표가 실재하는 최정밀)

레이어명이 요소의 정체다(A-WALL=벽, A-GLAZ=창…). ezdxf로 레이어별 추출.

```bash
python scripts/extract_dwg.py <도면.dxf> <작업폴더>
# → <작업폴더>/walls.json  (segments: [x0,y0,x1,y1,두께], 단위 m)
```
`.dwg`만 있으면 먼저 DXF로 변환(ODA File Converter 등). 산출 walls.json으로 **경로 D** 진행.

**이 스크립트의 알려진 결함 3가지 — 쓰기 전에 확인하라:**
1. **`$INSUNITS`를 안 읽는다.** `SF=0.001`(mm→m) 고정이다. 도면 단위가 mm가 아니면 축척이
   통째로 틀린 채 그럴듯하게 나온다. 로그의 건물 전체 치수(m)를 상식선과 **반드시 대조**하라.
2. **Layer 0을 전부 벽으로 본다** (`if name == "0": return "WALL"`). 실무 DWG에서 Layer 0은
   잡동사니가 모이는 곳이라 쓰레기가 벽이 된다.
3. **문/창을 분류만 하고 쓰지 않는다.** `cat_layers['DOOR']`를 만들어놓고 참조하지 않아
   벽이 통짜로 나온다. 개구부가 필요하면 경로 E로 가거나 직접 잘라라.

※ `pip install ezdxf`. explode된 조각 주의.
※ 경로 A에는 시각 검증 산출물이 없다(B는 preview.png, C는 overlay.png가 있다). 로그 숫자로 대조하라.

## 경로 B — 치수 없는 벡터 PDF

pdfplumber로 검정 벡터선 추출 → 수평/수직/사선 분류 → 평행선쌍 매칭으로 중심선+실두께 →
networkx로 고립 잡선 제거.

```bash
python scripts/extract_pdf.py <도면.pdf> <작업폴더> [건물폭m] [사선컷비율]
# 건물폭m 생략 시 50m 가정(임의 축척). 실치수를 알면 반드시 넣어라 — 축척의 유일한 근거다.
# 사선컷비율(0~1, 선택): 그 비율(상단 기준) 아래의 사선 제거 — 주차 램프 빗금이 벽으로 잡힐 때만.
#   기본은 사선 유지(무조건 제거하면 다른 도면의 하단 사선 벽이 조용히 소실된다).
#   ★ 2026-07-10 이전 버전은 0.45 컷이 하드코딩돼 있었다 — 과거 결과 재현이 필요하면 0.45를 명시.
# → <작업폴더>/walls.json + preview.png (추출 검증용 2단 비교)
```
※ `pip install pdfplumber networkx matplotlib`
**preview.png를 먼저 눈으로 확인**하라 — 벽선이 제대로 잡혔는지, 잡선이 남았는지.

## 경로 C — 치수 없는 래스터 (스샷 / 사진)

### 붙여넣은 이미지를 파일로: transcript에서 추출
채팅에 붙여넣은 이미지는 파일 경로가 없다. 세션 기록(jsonl)에 base64로 있으니 꺼낸다:
```python
# ~/.claude/projects/<프로젝트>/<session-id>.jsonl 각 줄을 순회하며
# {"type":"image","source":{"type":"base64","data":..}} 를 디코드 → .png 저장
```
(전용 스크립트는 없다 — 위 패턴대로 즉석 작성. session-id는 scratchpad 경로에 있다.)

### C-1 자동추출 (OpenCV+skimage)
색아이콘 제거 → 솔리드 블롭 제거 → Canny → 밴드화 → 노이즈 제거 → **skeletonize** →
그래프 추적 → 단순화.
```bash
python scripts/extract_raster.py <이미지.png> <작업폴더> [건물폭m]
# 건물폭m = 벽 bbox 가로 실치수. 제원 홀폭으로 역산: 홀폭m × (bbox_px / 홀_px)
# → walls.json + overlay.png
```
**overlay.png(원본 위 빨간선=검출벽)를 반드시 눈으로 검증**하라. 아이콘 스크리블이 남으면
색마스크 팽창↑, 갭이 크면 Canny 하한↓·maxLineGap↑.
※ `pip install opencv-python-headless scikit-image numpy`
※ walls.json에 `wall_height: 3.5`가 박힌다(실증 당시 값). 다른 층고면 빌드 전에 고친다.
※ **선만 나오고 "이건 문, 저긴 안방"은 모른다.** 실명·개구부가 필요하면 경로 E가 낫다.

### C-2 수기 rooms (도면이 색블록/단순 홀 위주일 때)
제원표가 축척을 준다. 예시: `examples/convention-center-rooms.json`.
```json
{
  "rooms": [{"name":"컨벤션홀","cx":24,"cy":34,"w":48,"d":30.6,"h":7.1,"t":0.30,"rot":0,"door":["S",8]}],
  "polylines": [{"pts":[[48,30],[62,27],[76,20]],"t":0.2,"h":3.0}]
}
```
`cx,cy`=중심(m), `w,d`=가로·세로, `h`=천장고, `t`=벽두께(기본 0.3/칸막이 0.15),
`rot`=회전각(도), `door`=`[N|S|E|W, 개구부폭]`.

**정직 원칙:** 래스터는 "**홀은 제원대로 정확, 배치·복도는 눈대중 재구성**"이다. 보고 시 이 구분을
반드시 명시하라. ASURA는 근사물을 정확한 척 넘기는 것에 민감하다.

## 경로 D — 매스 빌드 (A·B·C 공통, 빠른 검토용)


## 품질 등급 — 결과물에 반드시 붙인다

등급을 숨기면 받는 사람이 **시공도면으로 오해한다.** `build3d.py` 가 실제로 들어간 것을 보고
자동 판정해 `proof-log.json` 에 기록하고 콘솔에 `TIER T2` 로 찍는다. **보고할 때 이 등급을 같이 적어라.**

| 등급 | 내용 | 쓸 수 있는 곳 |
|---|---|---|
| **T0** | 벽만 압출 (경로 D) | 배치 확인 |
| **T1** | T0 + 바닥 + 개구부(인방·창대) | 구조 검토 |
| **T2** | T1 + 문짝·유리·장비·재질·조명·레이어 (경로 F 기본) | 실사화 i2i 입력·클라이언트 검토 |
| **T3** | T2 + 실측 재질·베이크·세부 가구 | 미구현 (Archipack·Bonsai 도입 후) |
| **T4** | 예약 | 시공 도서 수준 |

`proof-log.json` 에는 등급·프로파일·요소 개수·사용 레이어·**`meta.uncertain`(추정한 것)**·
`scale_ref`(축척 근거)가 함께 들어간다. **사용자 보고의 "추정한 것" 항목을 여기서 그대로 가져와라** —
근사한 부분을 정확한 척 넘기면 신뢰가 무너진다.

## 정확도 한계 — 보고할 때 그대로 밝혀라

- 경로 E 오차는 대체로 **±50~150mm**. 계획·검토·견적 베이스는 충분, **시공 발주 도면으로는 안 된다.**
- 곡선벽·복층 미지원(직선만). 의자·테이블 등 세부 가구는 도면에 없으면 **지어내지 않는다.**
- 저작권: 네이버·분양사 평면도는 저작물이다. 내부 검토는 통상적이나 **대외 납품물에는 쓰지 않는다.**
