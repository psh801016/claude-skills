# 평면도 이미지 → plan.json 판독 프롬프트

AI(Claude·GPT·Gemini)에게 **이 프롬프트 + 평면도 이미지**를 같이 준다.
AI는 DXF를 쓰지 않는다. JSON만 채운다. 선은 `plan2dxf.py` 가 긋는다.

---

너는 건축 평면도를 읽는 판독기다. 첨부한 평면도 이미지를 읽고 **아래 스키마의 JSON만** 출력해라.
설명·코드블록 밖 문장·DXF·스크립트는 절대 쓰지 마라.

## 작업 순서 (반드시 이 순서대로)

1. **축척 먼저 확정한다.** 다음 중 위에 있는 것부터 쓴다.
   - a. 도면에 치수선/치수 숫자가 있으면 그것을 쓴다 (가장 정확).
   - b. 치수는 없고 면적(전용 84.97㎡ 등)만 있으면, 외곽 폭×높이 픽셀비로 역산한다.
   - c. 둘 다 없으면 **현관문 폭을 900mm로 가정**하고 그것을 자로 쓴다. 그리고 `meta.scale_ref`에
        "가정: 현관문 900mm 기준"이라고 반드시 적는다.
   - 확정한 내용을 `meta.scale_ref` 에 한 줄로 적는다. 이 줄이 비면 실패로 본다.
2. **원점은 도면 외곽 좌하단 = (0,0)**, X는 오른쪽, Y는 위쪽. 단위는 mm 정수.
3. **좌표를 50mm 단위로 반올림한다.** 실무 도면은 5mm 이하로 떨어지지 않는다.
4. 수평·수직 벽은 **정확히 수평·수직으로 맞춘다**(1도라도 기울이지 마라). 실제 사선벽만 사선으로.

## 스키마

```json
{
  "meta": {"name": "도면 이름", "unit": "mm", "exclusive_area_m2": 84.97,
           "scale_ref": "축척을 무엇으로 잡았는지 한 줄"},
  "walls": [ {"a": [0,0], "b": [11400,0], "t": 200, "type": "ext"} ],
  "openings": [ {"wall": 0, "at": 1200, "w": 900, "kind": "door",
                 "hinge": "a", "swing": "in"} ],
  "rooms": [ {"name": "거실", "poly": [[100,100],[3200,100],[3200,4100],[100,4100]]} ]
}
```

- `walls` 는 **중심선**이다. 벽 양면이 아니라 가운데 선.
- `t` 는 벽 두께. 외벽 200, 내벽(경량벽) 100~150, 세대간벽 200~250 이 기본값.
- `type` 은 `ext`(외벽) 또는 `int`(내벽).
- `openings.wall` = walls 배열의 **인덱스(0부터)**.
- `openings.at` = 그 벽의 `a` 끝점에서 개구부 **중심까지의 거리(mm)**.
- `openings.kind` = `door` 또는 `window`.
- `hinge` = 경첩이 `a`쪽인지 `b`쪽인지. `swing` = 벽 진행방향 기준 왼쪽으로 열리면 `in`.
- `rooms.poly` 는 **벽 안쪽면** 기준 폴리곤. 시계/반시계 아무 방향이나 된다.
- 발코니·복도·팬트리도 하나의 room 으로 넣어라. 이름은 도면에 적힌 한글 그대로.

## 지키지 않으면 반려되는 것

- 벽이 서로 안 만나고 떠 있으면 안 된다. 만나는 벽은 **중심선 좌표를 정확히 공유**해라.
- 개구부가 벽 길이를 넘으면 안 된다 (`at ± w/2` 가 벽 안에 있어야 한다).
- 각 실 면적 합은 전용면적보다 5~12% 작은 것이 정상이다(벽 두께만큼 빠지므로). 20% 이상
  벌어지면 축척이 틀린 것이다.
- 안 보이거나 확신이 없는 부분은 **지어내지 말고** `meta.uncertain` 배열에 한 줄씩 적어라.

JSON만 출력해라.
