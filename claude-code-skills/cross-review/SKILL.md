# cross-review — 적대적 3중 교차검증

만들거나 고친 결과물을 혼자 판단하지 않고, 독립 모델들에게 **기본적으로 결함을 가정**하고 반박하게 한다.

## 절차

1. 검수 대상과 핵심 질문을 1200자 이내로 정리한다(파일 경로·구조·구체 질문 포함).
2. 세 관점을 병렬로 호출한다 — 누구 하나 빼지 않는다.
   - `gemini` — 다른 관점 / UI·UX 대안
   - `opus-ag` — 설계 · 로직 · 엣지케이스 (`opus-ag` 우선, 쿼터 소진(RESOURCE_EXHAUSTED)·실패 시 `opus`(claude CLI) 폴백 — 인증 상태가 가변이니 폴백 사용 전 짧은 스모크(PONG)로 확인. 실측 2026-07-06~08: 폴백 안정 동작)
   - `codex`(또는 `gpt`) — 실제 코드 버그 · 타입 안전성
3. 호출은 적대적으로 강제한다(검수자가 "잘 봐주지" 않도록):

   ```powershell
   cd C:\Users\PSH\dev\multi-model
   .\consult.ps1 -Provider codex   -Review -Retries 2 -Prompt "이 코드 검수: <질문>" -File "<경로>"
   .\consult.ps1 -Provider opus-ag -Review -Retries 2 -Prompt "이 설계 검수: <질문>"
   .\consult.ps1 -Provider gemini  -Review -Retries 2 -Prompt "이 관점 검수: <질문>"
   ```
   - Codex 사용자는 `consult.ps1`을 `shell`로 실행하면 동일하게 동작한다.
   - **대용량 입력 주의**: **15KB 이상** 파일을 -File로 통째 보내면 opus 계열이 타임아웃한다(실측 2026-07-03·07-04, 15KB도 3연속 타임아웃). 큰 대상은 분할하거나, opus에는 쟁점 요약을 보내 **중재/판정** 역할을 맡긴다 — 단 요약 중재는 원문 검수와 등급이 다르므로 보고에 "원문 검수 N + 요약 중재 M"으로 분리 표기한다. 긴 프롬프트·파일 첨부는 처음부터 `-TimeoutMs 420000`.
   - **codex 빈 응답 트러블슈팅**: ① -File 첨부에서 빈 응답이면 파일 내용을 -Prompt에 인라인해 재시도(실측 2026-07-07). ② 인라인도 빈 응답이면 CLI 버전↔기본 모델 불일치 의심 — `~/.codex/config.toml`의 model을 구버전 CLI가 지원 못 하면 400으로 죽어 빈 응답이 된다(실측 2026-07-10: gpt-5.6-sol ↔ npm codex 구버전). `npm i -g @openai/codex`로 업그레이드 후 재시도.
4. **레그 실패 처리 (조용한 누락 금지)**: 어느 레그든 실패하면 ① 프록시 상태 확인 후 기동(`antigravity-claude-proxy start`, gemini·opus-ag=8080) ② 재시도(-Retries 2가 흡수) ③ 그래도 실패하면 그 레그를 조용히 건너뛰지 말고 **실패 사실을 결과 보고에 명시**한다. 2중 검수를 3중이라고 보고하면 검수 실패다.
   - **세 레그가 한꺼번에 죽으면 모델 문제가 아니라 환경 문제다** — 재시도를 늘리지 말고 `multi-model-chain-recovery` 스킬로 넘어간다(Codex 샌드박스 소유권 / Claude OAuth 만료 / Gemini 폴더 미신뢰). 무인 루틴이라면 시작 전에 `preflight-chain.ps1`을 먼저 돌린다.
5. 세 결과를 대조해 BLOCKER/MAJOR/MINOR로 분류하고, 이견이 갈리면 가장 보수적·안전한 쪽을 채택한다. 검수 피드백도 산출물이다 — 반영 후 "이 정정 자체가 틀렸나" 역방향 재검토를 1회 돌린다(과잉판정 필터, **1차와 다른 모델에게 맡긴다 — 검수자 swap이 신선한 시각으로 유효 BLOCKER를 더 잡는다**).
6. **실증 검증 후에만 "통과" 보고** — 산출물 유형별 기준:
   - 코드: build / test / HTTP 200 등 실제 실행
   - 문서·설계·스킬(SKILL.md): 참조 경로·명령·도구명의 실재 확인(파일 존재, dry-run, 현재 세션 도구 목록 대조), 수치·규격의 원출처 대조
7. 배운 교훈은 `C:\Users\PSH\MultiAgent\_shared\learnings.md`(append-only, 운영 교훈)에 누적하고, 재사용 가치가 높은 도메인 지식은 AUSURA vault(`G:\내 드라이브\AUSURA\AI-Sessions\wiki\`)에 기록한다.

## 출력 형식

- **BLOCKER** — 머지/배포 차단. 근거·재현 시나리오 포함.
- **MAJOR** — 주요 결함. 구체적 수정안.
- **MINOR** — 개선 권장.
- **통과 가능 여부** — 위를 고쳤을 때만 통과인지 조건 명시.

네 항목은 결함이 없어도 **항상 출력**한다(조건부 생략 금지) — 해당 등급 결함이 없으면 "없음"과 그렇게 판정한 근거를 기재한다. 근거 없는 통과 선언은 검수 실패로 간주한다.

## 재귀 가드
이 스킬이 만든 검수 보고서 자체는 재검수 대상에서 제외한다(자기 출력 재입력 금지). "검수 결과를 또 검수해줘"는 수정이 반영된 새 산출물이 생겼을 때만 허용한다.
