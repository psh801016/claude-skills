# 족자봉 출력 정리 (업체 백월 → 출력 시트)

전시 참가업체 백월을 **족자봉**으로 뽑을 때, 업체가 준 파일을 출력 사이즈에 맞게 정리하는 일.
**요청서 1번 표의 '디자인 수령' 칸이 O 인 업체만 한다.** '디자인 파트 제작중', '디자인 수정, ○일 전달' 처럼 O 가 아닌 업체는 디자인 파트 몫이라 만들지도, 대기 목록에 올리지도 않는다 (ASURA님 지시 2026-10-22 — 드림·넷코아·국제식물). 재질이 후렉스·켈지이고 사이즈가 '별도 요청'인 업체도 디자인 수령이 O 면 내 몫이다 — 빠뜨리지 말고 목록에 올리되, **사이즈는 담당자 확인을 받은 뒤 만든다** (부산 2026 아이티윈 외 4사, 2026-10-22).

**이미지를 만들지 않는다.** 업체 원본을 자르고·줄이고·배치할 뿐이다. 디자인을 바꾸지 않는다.
이 문서는 규칙만 적는다. 규칙이 생긴 반려·사고·사용자 말은 `references/lessons.md`(날짜순)에 있다.

## 산출물 (사내 양식 — `출력\카페테리아_출.ai` 와 같은 꼴)
- **`…\발주\원본\족자봉\` 한 폴더에 몰아서** `<업체>_출.ai` + `<업체>_출.jpg` (ASURA님 지시 2026-10-22 — 업체 폴더마다 따로 넣지 않는다)
- 대지 1장, **1/10 축척**, 좌상단 제목 `<업체> — 족자봉`
- **시트 바탕은 연회색(CMYK 0,0,0,25)** — 맨 아래 잠긴 '시트 바탕' 레이어. 흰 바탕 판이 흰 시트와 구분 안 돼서 (ASURA님 지적 2026-10-23).
  이미 만든 시트에는 `add_sheetbg.jsx` 로 추가(두 번 돌려도 하나만). 다시 저장하면 점선의 점 위치가 미세하게 달라질 수 있으나 내용 변화 아님
- 판마다 위에 라벨 3줄: `<재질>`(기본 24pt 검정) / `족자봉 <W>mm x <H>mm` / `<위치> / <수량>EA`
- 재질을 60pt로 크게 + 색 구분(현수막 빨강 0,100,100,0 / 페트지 파랑 100,60,0,0)은 **행사 옵션**이다. 2026 부산 행사에서 동료가 따로 요청해서 쓴 것이라 기본값이 아니다(ASURA님 2026-10-26). 그 행사에서 요청이 있을 때만 jobs.js 에 `var BIG_MAT = true;` 를 넣는다.
- **같은 디자인은 한 번만 그리고 수량을 적는다** — 조각에 `qty: 2` 를 주면 `2EA` 로 나온다(2026-10-26 안랩 켈지). 재질명이 족자봉이 아니면 `l1:"그레이켈지"` 처럼 첫 줄을 바꾼다. 시트 전체가 한 재질이라 제목에 재질을 쓴 경우(켈지 등)는 job 에 `oneMat: true` — 라벨이 `판 이름`(34pt) / `950 x 650mm / 2EA`(22pt) 두 줄로, 제목(48pt)보다 작게 나온다.
- 라벨 글꼴은 굵은 글꼴(Pretendard Bold → 맑은 고딕 Bold)만 쓴다. 못 찾으면 가는 글꼴로 넘어가지 않고 멈춘다. `textFonts.getByName` 은 설치 안 된 글꼴(이 PC 의 Pretendard)도 돌려주고 대체 글꼴로 가늘게 찍히니 설치 목록에서 이름으로 찾는다(2026-10-28 이글루 재빌드에서 발견).
  (동료 요청 2026-10-22·23 "현수막, 패트 구분되게 크게, 색깔도 다르게"). 판 폭보다 넓으면 첫 줄을 자동으로 줄여 이웃 라벨과 안 겹치게
- **판마다 판 크기와 같은 흰판(CMYK 0,0,0,0)이 맨 아래에 기본으로 깔린다** — 바탕 없는 판 금지(ASURA님 지시). `check_bg.py` 로 빈 곳 0% 확인
- **상·하단 70mm 안쪽에 글자·그림이 있으면 안 된다**(족자봉 봉·마감에 가림, 동료 요청) — `check_margin.py` 로 판마다 재고, 걸리면
  **내용을 같은 비율로 줄여(필요하면 옮겨) 위아래 72mm 안쪽에 넣고, 남는 가장자리는 축소된 그림의 끝 2mm 띠를 그림으로 바꿔(rasterize) 늘려 채운다**
  (ASURA님 지시 2026-10-23). jobs.js 끝 `SAFE_M` 에 원래 위·아래 여백(실측값)을 넣으면 build.jsx `safeFit()` 이 처리 — 벡터 사본을 늘려 숨기지 않는다
  - ★ **늘린 가장자리가 단색일 때만 허용한다.** 무늬·그라데이션·선이 걸린 가장자리를 늘리면 줄무늬로 번진다(2026-10-28 제이콥 우측·앤앤에스피·우리아이티·시큐어레터 우측2, ASURA님 "임의로 늘리면 안 된다, 안 되면 파일을 달라고 해야 한다"). 빌드 뒤 `check_stretch.py` → STRETCH_OK 여야 납품한다. STRETCH_BAD 판은 늘리지 말고 **업체에 '상·하단 7cm 안쪽에 글자·로고가 없게 재배치한 파일'을 요청**하고, 받기 전까지 무엇을 납품할지는 ASURA님께 묻는다.
  - 업체 그림이 저해상도면(실물 70ppi 이하, 신화 삼각형·이글루 배경 19ppi) 우리가 보정하지 않고 업체에 고해상도·벡터 파일을 요청한다. 자동 업스케일은 거의 나아지지 않았다(신화 실측).
  - 업체가 7cm 맞춘 파일을 다시 보내면 jobs.js 의 그 판 `SAFE_M` 항목을 지워 여백맞춤(축소·늘림)을 끄고 원본 그대로 넣는다. 업체가 준 7cm 점선 PDF 는 참고용이고 출력은 .ai 로 한다(점선이 .ai 에 없는지 확인). check_margin 이 배경 도형 때문에 0mm 로 잡으면 글자·로고 위치를 눈으로 본다(2026-10-29 제이콥 좌·우 재전달).
- 판은 슬라이드 순서 **좌측1 · 좌측2 · 정면 · 우측1 · 우측2** (좌측1이 가장 바깥)
- **정사이즈**(재단 여유 없음). 글자 전부 깨기, 링크 그림 0, **RGB 0 — RGB 원본은 '색 맞춤' 변환** (아래)

## 원본 유형 → jobs.js 쓰는 법

| 원본 상태 | 판정 | jobs.js |
|---|---|---|
| 대지 = 정사이즈 | 그대로 | `A("x.ai", 대지번호, W)` |
| 대지 = 정사이즈인데 pymupdf 가 +2~10mm | 재단 여유는 PDF 쪽에만 있다. 일러 대지가 기준 | `A(...)` 그대로 (대지로 자름) |
| 1/10 · 1/2 축척 (290×235, 1450×1175) | 축척만 다름 | `A(...)` — dst 폭으로 알아서 키운다 |
| 대지 하나에 판 둘 (1800×1200) | 나누기 | `R("x.ai", [0,0,900,1200], 900, {ab:1})`, `[900,0,…]` |
| 펼친 한 장 (6500×2350 EPS) | 프레임 찾아 자르기 | `R("x.eps", rect, W, {frame:[6500,2350]})` |
| 비율 같은 다른 크기 PDF (381×508) | 확대 | `R("x.pdf", null, 900, {page:n})` |
| 다른 부스용 원본 (3880×2600 등) | **재배치** — 아래 |

**재배치**(제이콥 예시 참고): 내용은 판 **위쪽**에, 남는 아래는 배경으로 채운다(하단은 안내데스크·집기에 가려진다).
- 폭 맞춰 축소: `{src, rect, dst:[x, y, 폭]}` — 높이는 비율대로
- 배경 늘리기: `{src, pick:"back", dst:[0,0,900,1200]}` — 원본 맨 뒤 면(그라데이션 포함)을 판 크기로 늘림
- 띠·단색: `{src, rect:[띠 일부], dst:[0,0,900,104]}` (비균등) 또는 `fills: [[x,y,w,h,C,M,Y,K]]`
- 링크 깨진 원본: pymupdf 로 PDF 층 그림을 뽑아 CMYK TIFF → `{img:"x.tif", dst:[0,0,900,1200]}`

## 글줄 다시 배치 (판 경계에 걸리는 글자)
글자 크기는 되도록 그대로 두고 **단어 단위로 줄을 바꾼다**. 그래도 넘치면 문구 덩어리를 같은 비율로 줄인다.
1. 결과 시트를 판 경계(900)에 빨간 선을 그어 렌더 → 어느 줄이 걸리는지 본다
2. 일러에서 글자 조각(CompoundPath) 좌표를 뽑아 **단어 사이 틈**(글자 간격보다 큰 x 간격)을 찾는다. EPS 는 좌표가 통째로 밀려 나오므로 결과 시트의 실측 위치와 맞춰 쓴다
3. jobs.js 의 해당 조각에 `pre: [...]` — 자르기 전에 원본 사본에서 실행된다 (원본 파일은 저장 안 함)
   - `{ region:[x,y,w,h], move:[dx,dy] }` 영역 안에 통째로 든 객체를 옮긴다 (아래로 내린 줄만큼 그 아래 줄들도 같이 내린다 — 아래 줄부터 먼저)
   - `{ region, scale: 0.88 }` 묶음을 왼쪽 위 기준으로 같은 비율 축소
   - `{ region, hide: true, minW: 1000 }` 이 판에서만 숨김 (minW 로 큰 그룹만 — 글자 조각은 제외)
4. 같은 원본을 쓰는 이웃 판(좌측1·좌측2)에는 같은 글줄 이동을 둘 다 넣는다. 반대편 날개도 같은 꼴(두 줄 제목)로 맞추면 보기 좋다
5. 글줄을 옮긴 판은 verify.py 가 숫자 비교를 건너뛰니 **반드시 눈으로** 본다
6. 글줄을 새로 짤 때 크기 위계(제목 크게·보조 작게)와 색 역할은 업체 원본을 따른다 — 우리가 디자인을 바꾸지 않는다. 판단이 필요하면 AUSURA `wiki/playbooks/design-color-sense.md` 의 적용 체크로 본다
실례(examples/busan_2026/jobs.js): 위드 `WITH_TEXT`·`WITH_L1`(3줄로 바꾸고 기기 그림은 좌측2 로), 신화 `SHIN_L`·`SHIN_R`('Contain the / Breach', 'Illumio / Insights').

## RGB 원본 색 맞춤
probe.jsx 에서 문서 색공간이 RGB 이거나 RGB 그림이 있는 업체가 대상 (부산: 소만사·우리아이티·신화).
**일러 변환에 맡기지 않는다** — 일러가 새로 만드는 CMYK 문서는 U.S. Web Coated(SWOP, 미국) 기준이라 국내 인쇄에서 틀어진다
(우리아이티 파랑 ΔE 16.5, 신화 주황 6.5 실측). 기준은 **Japan Color 2001 Coated**(사내 표준), 종이 흰색 기준 상대 색도.
- **단색(벡터 면·선·그라데이션 정지점)**: `scripts/color/match.py best()` — 표준 변환(상대색도+BPC)에서 출발해 C·M·Y·K 를 1% 씩 움직여
  원본 RGB 와 ΔE2000 이 가장 작은 값을 찾는다. 총 잉크 300% 이하, 밝은 유채색엔 K 를 넣지 않는다, **검정·회색은 K 단독**(검정 = K100)
- **그림**: 픽셀마다 표준 변환(상대색도+BPC), 넓은 단색 면만 best() 값으로 덮어써 벡터와 이음매 없이
- 순서 (작업 폴더 C:/jjb/color 에 scripts/color/* 복사):
  1. `run_cm.jsx`: `var KEY="<key>", MODE="export", SRCS=[["원본",쪽]];` + `$.evalFile(".../colormatch.jsx")` → run_ai.ps1
     원본(RGB 문서)에서 색 목록과 RGB 그림(픽셀 크기별 1장)을 뽑는다. **결과 시트에서 뽑으면 안 된다 — 저장할 때 일러가 이미 SWOP CMYK 로 바꿔 둔다**
  2. `python -X utf8 colorize.py map <key>` → 색표 + 그림 CMYK TIFF → `<key>_map.js` (색마다 표준값·최적값·ΔE 출력)
  3. MODE="apply" → 결과 시트에서 일러가 바꾼 값을 열쇠로 최적값으로 바꾸고, 같은 픽셀 크기 그림을 TIFF 로 갈아 끼운다 (로그 rasters_unmatched=0 확인)
- **PDF 원본에 투명 마스크 그림이 많으면**(우리아이티 ~290개) 일러가 손댈 수 없는 객체로 들여 와 위 방법이 안 먹는다 →
  `colorize.py pdf <pdf> <쪽> 900 1200 200 <out.tif>` 로 판 전체를 색 맞춤 TIFF(200dpi)로 만들어 `{img:...}` 로 쓴다
- 확인: 14개 전부 `fitz` 로 그림 색공간 검사(Indexed 는 기본 색공간까지) → RGB 0, 저장본에서 그림 픽셀값이 넣은 값과 같은지(주황 0,196,252,0)
- 결과 문서의 프로파일 표기는 SWOP 로 남는다(스크립트로 못 바꿈). 숫자는 Japan Color 기준으로 맞춘 것 — 보고에 적는다

## 요청서 차수가 바뀔 때 (1021 → 1022 실례)
1. `diff_request.py` 로 두 판을 덤프해 diff — 표·문구·그림 해시가 바뀐 슬라이드만 본다
2. '수정 필요' 슬라이드의 메모 그림(업체 메일 캡처)을 꺼내 읽는다 — 무엇을 왜 바꿨는지가 거기에만 있다
3. 경로 속 새 파일명(예: `_수정-01`, `_최종 (1)`)을 Z: 에서 찾아 옛 파일과 렌더로 비교 → src 교체(옛 것은 src_old)
4. 위치 교체 요청은 슬라이드 그림과 원본 대지를 대조해 jobs.js 의 대지 번호만 바꾼다 (소만사: 정면=대지3, 우측=대지2)
5. 업체가 '글씨 누락'을 말하면 우리 납품본을 먼저 렌더해 확인하고 사실대로 보고한다 (시큐어레터: 글씨 있음)

## 판 밖에 숨은 내용 금지
판에 걸친 큰 묶음을 통째로 복사하면 마스크 밑에 원본 전체가 숨어 들어가고, 비균등 확대(띠 늘리기) 때는 그게 수십 m 로 늘어난다
(제이콥 정면 띠: 원본이 28.2m 로 늘어나 2,800개가 숨어 있었다). build.jsx 는 **영역에 걸친 묶음은 안으로 들어가 닿는 것만** 가져온다.
- 마스크 묶음은 마스크가 판 영역을 다 덮을 때만 안으로 들어간다(그땐 마스크가 하는 일이 없다). 투명도·합성 모드가 걸린 묶음은 통째로
- 단색 띠·선은 원본을 늘리지 말고 `fills` 로 같은 CMYK 사각형을 그린다
- 확인: `t_hidden.jsx` → 판마다 '가장 멀리 뻗은 거리 / 판 밖 객체 수'. 남는 것은 업체 원본 마스크 안의 것이어야 한다 ("원본이 그러면 어쩔 수 없고")

## 반투명·합성 효과가 많은 원본은 그림으로
원본에 불투명도·합성 모드(곱하기·스크린·색상 닷지·오버레이)·녹아웃이 많으면 **1/10 로 줄이는 순간 효과가 빠진다**
(프라이빗: 반투명 3,109개·합성 7,900개 → 가운데 유리 타워가 파랗게 눌림 / 이글루: 빛줄기가 탁해짐). 100% 복사만으로는 멀쩡 — 원인은 축소.
- 찾기: `localdiff.py <결과폴더> <라벨칸mm>` — 판을 30칸 크기로 나눠 칸 평균색을 원본과 비교. verify.py(전체 형태)는 이걸 못 잡는다
- 고치기: 원본 쪽을 pymupdf 로 **CMYK 그대로 렌더**(2.9m 판 100dpi, 900 판 150dpi, Japan Color 태그)해 `{img:"x.tif"}` 로 쓴다 — 일러 밖에서 해서 강제 종료 위험도 없다
- 렌더본을 원본과 다시 칸 비교(차이 ≤ 20)해 확인

## 해상도 점검
- **래스터효과 해상도는 300ppi.** 일러 새 문서 기본값은 72ppi 라 1/10 시트에서 글로우·블러·그림자가 실물 7ppi 로 굳는다. 업체 원본은 대부분 300 이다. build.jsx 가 `doc.rasterEffectSettings.resolution = 300` 으로 고정한다. 굿모닝 빛 고리는 72 에서 둘레 청록 글로우가 빠졌고 300 에서 원본과 같아졌다. 라이브 효과가 없는 시트는 72·300 결과가 똑같다(나머지 15개사 전수 비교, 차이 0).
- `res_audit.py <시트.ai>` 로 사진마다 실물 ppi 를 본다(1/10 시트라 시트 ppi ÷ 10). xref 0 항목은 사진이 아니라 그라데이션이라 뺀다(확대하면 매끈하다). 폭 2~7px 로 길게 늘린 띠는 여백맞춤 가장자리 채움이라 정상이다.
- 40ppi 미만은 실물 100ppi 로 확대해 눈으로 본다. 업체 원본이 원래 낮은 것(굿모닝 배경 10ppi·스패로우 배경 22ppi)은 매끈한 그라데이션이면 문제없다. 우리 쪽에서 낮춘 게 없는지는 결과 사진의 픽셀 크기가 원본에도 있는지로 가린다.
- 업체가 같은 파일을 다시 보내면 대지별로 이전 원본과 렌더 비교해 바뀐 곳만 보고한다(굿모닝 10-27: 장식 점 배치만 바뀜).

## 함정
1. **오류 처리에서 모든 문서를 닫지 말 것.** 빌드 중 ASURA님이 같은 일러에 다른 행사 문서(저장 안 함)를 열었다. build.jsx 는 `closeMine()` 으로 C:/jjb 아래 문서만 닫고, 끝나면 원래 문서를 다시 앞으로 띄운다.
2. **pymupdf 크기 ≠ 일러 대지.** PDF 층은 재단 여유(소만사 +2, 윈스 +5, 워터월 +3)를 포함해 잰다. 정사이즈 기준은 일러 대지.
3. **Affinity EPS 맨 앞 빈 줄** 때문에 일러가 "operation was cancelled" 로 못 연다 → `%!PS` 앞을 잘라낸 사본으로 연다. sK1 이 만든 옛 .ai 도 못 연다 → 같은 폴더 EPS 사용.
4. **.ai 를 .pdf 로 이름만 바꿔도 일러는 AI 데이터를 연다** → 링크 깨진 그림은 그대로 빈칸. pymupdf 로 PDF 층 그림을 뽑아야 한다.
5. **원본에 숨은 가이드선**(대지 밖까지 긴 세로선)이 있다 → `guides`·`hidden` 은 건너뛴다.
6. 업체 .ai 가 PPT 를 옮긴 껍데기일 때가 있다(우리아이티: 글자만 있는 대지 20개). 같은 폴더 PDF 가 진짜다.
7. 검증 점수: 색 변환(RGB→CMYK·혼합 공간) 때문에 MAE 는 6~12 가 정상. `verify.py` 는 48px 로 줄인 형태 상관 ≥0.95 **또는** 밝기 차 ≤6 이면 통과. 단색 판은 상관이 낮게 나온다. 숫자로 안 보는 판(재배치·EPS)은 반드시 눈으로.
8. 1/10 축척 소형 대지(90×120)는 위치 자동 대조 썸네일이 작아 틀린다 → 대지 순서 + 눈으로.
9. 펼친 날개(1800 폭)를 900 두 장으로 나누면 **가로지르는 글줄이 잘린다 → 잘린 채 두지 말고 다시 배치한다** (ASURA님 "글씨 잘리는건 알아서 잘 배치해", 2026-10-22). 위 '글줄 다시 배치' 참고.
10. 업체가 준 목업의 하단 줄무늬 = 족자봉 밑에 남는 부스 흰 판 표시. 출력 대상 아님 (김태영님 확인).
11. **ExtendScript 는 겹친 삼항식(`a ? x : b ? y : z`)을 틀리게 계산한다** → if 로 (pre 로그에서 실제로 터졌다).
12. Affinity EPS 는 일러 캔버스(5779mm) 가장자리 밖에 걸쳐 열린다 → 그 문서에서 대지를 프레임으로 옮기면 AOoC 오류. 대지는 건드리지 말고 프레임 원점만 쓴다.
13. **일러 강제 종료**(VCRUNTIME140 접근 위반)가 큰 EPS 를 연속으로 열다 한 번 났다 → 사용자 문서가 열려 있으면 절대 돌리지 않는다(run_ai.ps1). 이미 잰 값(색 목록 등)은 다시 열지 말고 재사용한다.
14. ExtendScript 에서 COM 으로 경로를 넘길 때 bash 의 `C:\\...` 는 깨진다 → PowerShell 인자는 작은따옴표 `'C:\jjb\...'`.
15. **화면 색이 다르게 보여도 CMYK 숫자는 같을 수 있다.** 업체 원본은 Japan Color 태그, 결과는 새 문서 프로필이라 pymupdf 색 변환만으로 결과가 더 보라색으로 렌더된다(굿모닝 10-27, verify 오탐). verify.py·localdiff.py 는 CMYK 원본이면 `fitz.TOOLS.set_icc(False)` 로 숫자끼리, RGB 원본(probe.txt 의 color=RGB)이면 켜서 비교한다. 의심나면 `colorspace=fitz.csCMYK` 로 렌더해 숫자를 직접 대조한다.
