# 현장사진 바레이션 (venue-photo-variation)

현장 사진 → **클린 플레이트** → (사용자) 3D 합성 → **재실사화**. 이미지 생성은 사용자가 이 요청에서 만들라고 했을 때만 한다(미디어 생성 가드). "만들어줘/진행해"는 생성 지시로 본다.

## 0. 시작 전 (항상)
- 받은 사진을 **전부** 보고 인벤토리를 본문에 적는다: 공간, 천장(샹들리에·트러스·프로젝터), 무대·스크린·커튼, 벽·문·비상구, 바닥 무늬, **지울 것 목록**, 어긋나는 점(카메라가 축에서 비껴 있음 등).
- 모호할 때 묻는 질문은 하나만: "무대 꽃장식·현수막처럼 행사 장식은 지울까요, 남길까요?" — 답이 없으면 **지운다**(합성 배경은 비어 있는 게 기본).
- 작업 폴더: `G:\내 드라이브\AI-작업기록\Claude\<YYYY-MM-DD>_<현장>-바레이션\`, 원본은 `00_원본.jpg` 로 복사. 최종 이미지는 `C:\Users\PSH\Downloads` 에만 둔다(프로젝트 폴더에 넣지 않음 — 2026-11-05 사용자 지시).

## 1. 클린 플레이트
```
python "C:\Users\PSH\.agents\skills\venue-photo-variation\scripts\variation.py" plate --src 00_원본.jpg --out 01_<현장>_정면_클린.png --view front
```
- `--view front` = 무대(정면벽) 축 위로 카메라 이동, 눈높이 1.6m, 24mm, 1점 투시. `--view keep` = 원래 시점 유지(로비·복도 컷 등 정면이 없을 때).
- 남길 장식은 `--keep "flower arches on stage"`, 추가 지시는 `--extra`.
- 성공 = `VARIATION_OK <경로> 2560x1440`. 프롬프트·로그가 결과 옆에 `.prompt.txt`·`.log.txt` 로 남는다. 출력 파일이 이미 있으면 멈춘다(새 번호로).
- 여러 컷(홀 정면·로비·입구 등)은 컷마다 한 번씩 돌린다.

### 검수 (통과 못 하면 재생성, 통과라고 납품하지 않는다)
- 세로선 수직, 무대·스크린 가로선 수평, 소실점이 무대 가운데인지.
- 지울 것 목록이 하나도 안 남았는지(의자 다리·테이블 그림자·케이블 포함).
- 천장 구조·샹들리에 개수·스크린 위치·문·비상구가 원본과 같은 디자인인지. **정면으로 시점을 옮기면 원본에 안 보이던 부분은 GPT 가 지어낸다** — 이 사실을 보고에 적는다(가려졌던 카펫 무늬 포함).
- 1차 실패 시 같은 등급으로 1번 더, 또 틀리면 `--extra` 로 틀린 곳을 콕 집어 지시.

## 2. 3D 올리기 (사용자 작업)
- 정면 플레이트면 3ds Max 카메라: 높이 1600mm, 24mm, 타깃은 무대 중심 같은 높이(수평), 렌더 2560×1440. 렌더는 알파 포함 PNG 로.
- 포토샵에서 플레이트 위에 렌더를 올려 합성본을 만든다(접지 그림자 없어도 됨 — 3단계에서 만든다).

## 3. 재실사화
```
python "...\scripts\variation.py" realize --src 02_합성본.png --plate 01_<현장>_정면_클린.png --out 03_<현장>_실사.png
```
- 3D 오브젝트의 디자인·위치·글자·로고는 잠그고 빛·그림자·반사·재질감·색온도·노이즈만 맞춘다(2영역: ZONE A 잠금 / ZONE B 실사화).
- 프롬프트 규칙(interior-prompt-maker 구도 보존 원칙): **초점거리 숫자 금지, 부정문 금지, GPT 에 NEGATIVE 없음.** 스크립트 프롬프트가 이미 지킨다 — `--extra` 도 긍정형으로만 쓴다.
- 여러 컷은 동시에 돌려도 된다(2026-10-27 2컷 병렬 성공).

### 3-1. 원본 복원 (항상 — 배경 + 그래픽)
GPT 는 3D 물건만 고치지 않고 **사진 전체를 다시 그린다** — 같은 홀인데 천장 천 명암·샹들리에·벽·카펫이 바뀐다(2026-10-27 반려: "배경 같은 곳인데 왜 틀어져", 천장 평균차 14.5). 그래서 **배경은 항상 원본 픽셀, 후보에서는 3D 물건(테이블·의자)만** 가져온다. 바닥 그림자·LED 스필은 `--floor-y` 아래에서만 밝기 비로 옮긴다.
또 GPT 후보는 **작은 글자·로고가 반드시 깨진다**(2026-10-27: 원형 문구 "for" 누락, 주최 로고 뭉개짐, 해상도 1672×941 축소). 후보를 납품하지 않는다.
```
python "...\scripts\restore_zone_a.py" --src 02_합성본.png --cand 03_후보.png --plate 01_클린.png --boxes "x1,y1,x2,y2;..." --floor-y <바닥 시작 y> --out 04_최종.png
```
- 박스 = 합성본 픽셀 기준 그래픽 영역(LED 면·현수막·키오스크 사인). **앞을 가리는 의자·사람은 박스 밖으로** 잡는다(박스 아래끝을 의자 윗선 위로).
- 마스크 = 박스 ∩ (합성본 − 클린 플레이트 차이) → 그래픽 외곽이 자동으로 정확해진다. 합성본은 클린 플레이트 위에 3D 를 얹은 것이어야 한다.
- **클린 플레이트가 없는 합성본**(2026-10-28 교통문화발전대회 컷): `realize` 는 `--plate` 없이 돌리고, restore 는 `--plate` 대신 `--obj-mask 물건.png`(3D 물건 흰색, 합성본 크기)를 준다. 마스크는 의자·테이블보 색(HSV 범위, 바닥선 아래만) + LED·무대 박스로 만든다. 박스는 화면마다 따로 잡는다 — 하나로 묶으면 옆 화면 위 벽까지 들어가 벽이 GPT 것으로 바뀐다. 카펫이 테이블보와 같은 색 계열이면 색상(H)만으론 섞인다 → 채도(S)로 가른다(2026-11-02 HUF: 3D 테이블·의자 S≥240, 실사 남색 카펫 S≈180 → S>215).
- 후보를 ORB 호모그래피로 원본에 정합한 뒤 박스 안만 원본 픽셀(× 후보의 저주파 밝기)로 되돌리고 2560×1440 으로 낸다. `_overlay50.png`·`_mask.png` 가 같이 나온다.
- 성공 = `RESTORE_OK … rms=<px>`. rms 1px 넘거나 inliers 수백 개 이하면 후보 구도가 틀어진 것 → 재생성. 단 같은 의자 수백 개처럼 반복 패턴이 화면을 채우면 rms 가 1~1.5px 로 뜨기도 한다 → 무대·벽·통로 경계를 확대해 이중선이 없으면 통과(2026-11-05 KOBC 1.44px, 경계 깨끗).
- 교실형 배치(테이블 + 의자 줄)는 줄 사이 회색 테이블 윗면이 색 마스크에서 빠진다 → 세로 긴 커널(71×5) close 로 메운다.
- `--floor-y` = 합성본 픽셀 기준 벽과 카펫이 만나는 y(무대 앞선 근처). 이 위(천장·벽)는 밝기까지 원본 그대로.
- **무대 위 장비 + LED 실사화(객석 있는 홀)** 는 `--color-gain --floor-y-end <무대 앞선 y> --obj-margin 5 --lock-graphics` 를 붙인다(2026-11-06 오디토리움). 안 붙이면 ① 물건 둘레만 GPT 의 보라 반사 바닥 → 얼룩 ② 객석까지 색이 바뀜(평균차 16) ③ 판넬 디자인 파랑이 ±20% 밝아짐. 붙이면 객석 차 0.0, 무대 바닥에만 LED 번짐이 고르게.
- 배경판이 고해상도로 따로 있으면(5120 업스케일 등) 합성본 배경 대신 그 판을 쓴다: 무대·스피커 박스 안에서만 (흐림 맞춘) 차이로 3D 물건을 떼어 고해상도 판 위에 얹은 2560 작업본을 `--src` 로 쓴다. 박스 없이 차이를 잡으면 좌석 윤곽(선명도 차)이 잡히고 어두운 스피커는 빠진다.
- 박스 아래끝을 앞 장비(무빙라이트) 위에서 자르면 판넬 아래 띠가 GPT 것(파란 띠)으로 바뀐다 → 장비만 피해 박스를 여러 개로 쪼개 판넬 밑단까지 잡는다. 작은 사인 박스는 둘레 바닥 번짐 때문에 검사 수치가 높게 나온다 → 마스크 안 픽셀차(≈0)로 따로 확인.
- 검수: 합성본 대비 천장 영역 평균차 ≈0(2026-10-27 0.2), 오버레이에서 판넬 네 모서리 이중선 없음, 확대(그래픽 경계·키오스크 하단·현수막 모서리)에서 테두리 띠 없음, 글자 원본과 동일.

## 4. 배경 교체 (rebg) — 3D 렌더의 구도·물건은 그대로, 배경만 실제 현장으로
**기본 = 한 명령(2026-11-06 업그레이드, 사용자 "공간 만드는거 업그레이드 시켜").** 렌더(물건만 알파) + 현장 사진이면 이것부터 쓴다:
```
python "...\scripts\space_rebg.py" --render 렌더.png --refs 현장.jpg --height-m 2.0 --wall-gap 2.2   --materials "<벽·바닥·천장 마감(긍정문, 사진에 있는 것만)>" --work 작업폴더 --final 결과.png [--n 3] [--soffit 2.9,1.8 --ceil 4.0 --tile ashlar --portal=-3.4,0,3]
```
- 순서: 알파 마스크 → **렌더 직선 RANSAC 으로 두 소실점·초점거리·눈높이 자동** → 앞 모서리(가장 긴 세로선, 카펫 제외) 자동 + `--height-m` 로 거리 → 벽 방향 자동(직선 많은 소실점 = 정면) → 벽·바닥·천장 밑그림 투영(`space_underlay.py`) → GPT rebg N장 병렬(GEOMETRY LOCK) → `restore_objects` → `check_vp` → VP_OK·rms≤1.5 중 최선 1장. 성공 = `SPACE_OK … vp=… rms=…`, 없으면 `SPACE_FAIL`(납품 금지, `--n` 늘려 재실행).
- **실사화까지 한 번에: `--realize`** (사용자 "다 실사화까지 해서 주는 거지?" — 배경만 바꾸면 부스가 CG 로 남는다). 배경을 맞춘 판을 GPT realize 1회 → `restore_zone_a --obj-mask 물건 --boxes 전체 --color-gain --obj-margin 5 --floor-y (가장 높은 접지점−30)` 으로 글자·형태·배경은 원본, 접지 그림자·바닥 반사·조명 감쇠만 가져옴 → `check_vp` 재확인. 결과는 사람 넣기(person-layer-maker '공간이 이미 완성된 판' 절)의 바탕이 된다 — 로그의 `f`·`hc`·소실점을 넘긴다.
- 후보는 **후보마다 다른 폴더**에 만든다(같은 폴더면 저장 실패한 codex 가 옆 후보 파일을 자기 결과로 냈다 — rms 0.0 으로 걸러냄).
- 천고(낮은 띠 `--soffit`, 높은 천장 `--ceil`)는 실측값으로(점검표 12). 성과보고회 로비 = 띠 2.5m·폭 1.8m, 코브 3.5m.
- `--wall-gap`: 물건 앞 모서리→벽(m). 사람이 뒤에 앉는 데스크 ≥2.0, 포토월은 깊이+0.5~1. **같은 현장 여러 컷은 벽선이 이어지게 맞춘다**(로비 데스크 2.2 ↔ 같은 줄 포토월 1.6).
- 소실점을 손으로 재거나 정면·측면 직선을 한 무리로 최소제곱하지 않는다 — 2026-11-06 로비에서 3527 이 3326 으로 치우쳐(눈높이 59px) "벽 라인 봐봐" 반려. `check_vp.ransac_vps` 만 쓴다.
사용자가 "이 렌더 배경을 경로(현장 사진) 참고해서 합성"이라고 하면 이것이다. **카메라를 사진에 맞춰 다시 세우는 일이 아니다**(2026-11-05 KOBC 로비: 사진 시점으로 데스크를 재투영하려다 "배경을 경로 참고해서 합성하라니까 너 뭐해" 반려).
```
python "...\scripts\variation.py" rebg --src 렌더.png --refs 현장1.jpg 현장2.jpg 현장3.jpg --out 03_후보.png --extra "<물건 뒤·좌·우·바닥에 올 실제 마감 배치(긍정문)>"
python "...\scripts\restore_objects.py" --src 렌더.png --cand 03_후보.png --obj-mask 물건만_알파.png --out 04_최종.png
```
- 물건만 렌더한 알파 PNG(같은 카메라, `render\등록데스크_2.png` 같은 것)가 있으면 그것을 마스크로 쓴다. 성공 = `OBJ_RESTORE_OK … rms≤1`, 물건 안은 원본 렌더 픽셀 × 후보 저주파 밝기.
- 참고 사진은 물건이 놓일 바로 그 벽·바닥이 보이는 컷 2~3장(평면도·3D 스샷으로 자리 확인). `--extra` 에 "뒤 = 루버 벽, 오른쪽 = 흰 곡면 벽, 바닥 = 청회색 카펫"처럼 자리별로 적는다.
- 2026-11-05 반려 "문 옆에 벽체 저런 거 들어가 있는데 너 뭐 보고 만든 겨 / 배경 똑바로": 참고 사진을 '같은 로비'라고 아무 컷이나 고르지 말고 **물건이 놓일 바로 그 벽**이 보이는 컷을 고른다. 사용자가 전에 확정한 같은 현장 합성본(예: 1일차 포토존)이 있으면 그것이 1순위 참고다. `--extra` 에 벽 재질을 지어내 적지 않는다(사진에 있는 것만).
