# 메인비주얼 → 사이즈 바레이션 발주 원본

디자인팀이 확정한 **메인비주얼 1장**을 기준으로, 행사 설치물마다 사이즈에 맞게 조각(제목·슬로건·인물·엠블럼·로고·배경)을 **재배치**해 발주 원본을 만드는 일. 메인이 바뀌면 전부 다시 만든다.
족자봉(`jokjabong-print-fit`)·간판(`illustrator-data-merge`)과 같은 **원본 → 출력** 발주 체계이고, 시트 양식(1/10·연회색 바탕·라벨)과 출력 굳히기(간판 스킬 8절)를 그대로 쓴다.

**이미지를 만들지 않는다.** 메인의 조각을 복제해 옮기고 줄일 뿐, 새 그림을 그리지 않는다.
이 문서는 **규칙과 절차만** 적는다. 규칙이 생긴 반려·사고·사용자 말은 `references/lessons.md`(날짜순), 디자인 검수 기준은 `references/design-quality.md`.

## ★ 작업 전 필수 — `references/order-design-rules.md` 를 먼저 읽는다 그 전에 `references/house-order-style.md`(사내 발주 45장 공통 꼴) 먼저.
발주 바레이션(판 구성 읽기·디자인 위계·1,700 규칙·날개·그룹 시트·라벨·속도)의 정본이다. 2026-11-03 KOBC 하루 반려 20여 건을 묶었다.
요약: 요청서 전 장 렌더 → 글꼴 대조 → CMYK 판 → 목공 +100 → 이틀이면 날짜별 세트 → 메인 조각 그대로·넓은 판은 그래픽 크게 → 타이틀·DAY·날짜·로고 줄 위 1/3, 글자는 바닥 1,700 위 → 날개는 색 그라데이션 + 흐린 행사명 → 그룹 시트(부산 라벨 꼴) + 발주 PPTX → 바뀐 것만 빌드 → **build_log 의 '겹침 검사 0건' + 미리보기 확인 뒤에만 보여 준다**.

## 절대 규칙
- **우리 몫은 `01 3D` 폴더 안(백월·LED 등 3D에 쓰는 설치물)뿐이다.** `02 메인비주얼`·`03 DID`·`04 현장설치물`(X배너·폼보드·켈지·네임택)·`07 명찰명패` 등 다른 번호 폴더는 **디자인팀 것** — 거기 파일을 발주 폴더로 복사하지도, 바레이션 대상에 넣지도 않는다. 참고로 읽는 것만 된다. **단, ASURA님이 그 파일을 `발주\원본` 에 직접 넣고 고치라고 하면 대상이다** — 같은 이름으로 덮어쓰고, 덮기 전에 작업기록 폴더에 `백업_<이름>_<날짜>_수정전.ai`.
- **`02 메인비주얼` 폴더는 읽기만 한다.** 저장·수정·새 파일·임시파일 어느 것도 만들지 않는다. 메인 .ai 는 `run.ps1` 이 `C:\mvv\src\main.ai` 로 **복사**해서만 연다. 메인 안에 옛 문구 레이어가 남아 있어도 고치지 않고 조각 영역으로 피해서 고른다.
- **발주 폴더 = `<행사>\01 3D\발주\`** 아래 `원본\`(오브젝트 살아 있는 .ai) · `출력\`(`_출.ai` 굳힌 발주용). 디지털물(LED·DID)은 발주가 아니다 — LED 는 `01 3D\map\` 의 3D 텍스처로만.
- **일러를 돌리기 전에 묻는다.** `run.ps1` 은 사용자 문서가 하나라도 열려 있으면 ABORT 한다. "저장하고 닫아 주시면 돌리겠습니다"로 묻고, 열려 있는 동안은 COM 으로 읽지도 않는다(드래그·대화상자 중이면 COM 읽기가 2분 넘게 멈춘다).
- **바레이션에는 날짜(일시·장소 줄)와 그 구분선을 넣지 않는다.** 제목·슬로건·인물·엠블럼·로고만 옮긴다.
- **치수·마감·디자인이 같은 판은 한 파일로 합치고 수량만 더한다**(예: 중앙·입구 백월 측면 날개 700x2640 → 1파일 4EA).
- **여유 표시는 보이는 면 대각선 두 모서리(왼쪽 위 ㄱ·오른쪽 아래 ┘)만** — 점선 사각형·네 모서리 전부 금지. 연회색(K40) 극세선, 한 변 실물 100mm(좁은 판은 면 폭의 20%). (2026-11-03 "240mm 너무 길다 100mm 정도만 하고 대각선 쪽만 표시해 / 사각 다 표시하지말고". 이전 관행 원본: 부산 2026 `3 3D\발주\원본\무대목공백월.ai`)
- 때에 따라 달라지는 디자인 판단(로고 위치 등)은 **두 안을 다 만들어** 보여 드린다. 임의로 하나만 고르지 않는다.
- **참고 이미지를 받으면 그 원본 파일부터 찾아 연다** — 캡처 속 시트(제목·치수 라벨)로 이전 행사 `발주\원본` 의 .ai·jpg 를 찾고, 판 외곽·테두리·글자 위치를 pymupdf 로 실측해 그대로 따른다. 기억이나 다른 행사 간판으로 짐작해 만들지 않는다.
- **"확정" 다음은 3D 맵 PNG** — 품목마다 맵 대지를 '스크린용 내보내기'로 뽑아 `map` 폴더에. 출력(_출)·모음 발주 시트는 따로 지시가 있을 때만.
- 사용자가 이미 맞다고 한 부분은 다른 부분을 고치면서 같이 바꾸지 않는다.
- **이 스킬은 말 안 해도 작업마다 고친다.** 끝나면 새 함정·수치를 여기와 `scripts/` 에 반영하고 `test_skill.py` 통과 → `python ~/.agents/check_skills.py` → `~/.agents/sync.ps1`.

## A. 흐름 — 바레이션 빌드
```
0. 자료 인벤토리   폴더 전체 + 열린 일러 문서(COM 읽기, 사용자가 쉬고 있을 때만) + 기존 바레이션 jpg 를 전부 본다.
                   표: 항목 / 대지 치수 / 메인 요소 / 옛·새 비주얼 여부. 옛→새 바뀐 요소 표(캘리·슬로건·시간·장소·인물·로고).
1. 치수 판정       ★ 목공 불칼질 사내 기본 = 사방 100, 슬로프가 있으면 위아래 200씩(목공슬로프). 요청서에 여유가 적혀 오면 그 값이 우선 — "상하좌우 20" 은 각 변 20cm = 200mm(목공200).
                   시공·마감으로 체계를 가른다 → python scripts/sizes.py <목공|옥타|후렉스|켈지…> W H [마감]

                   근거 정본: AUSURA wiki/reference/octanorm-booth-order-specs.md. 시공 방식은 묻는다(파일 치수로 추정만 하고 단정 금지).

3. jobs.js         examples/chungnam_2026/jobs.js 를 복사해 고친다: PIECES(조각 → 원본 영역) + JOBS(항목 → W/H/bleed/재질/위치/수량/layout).
                   판형 4계열: 가로형(백월·LED·폼보드) / 세로형(X배너·DID·족자봉) / 원형·정방(켈지·명패) / 띠형(날개·측면 세로쓰기).
                   // 검산: <시공> <W> <H> = <발주W>x<발주H>  주석을 항목마다 달면 test_skill.py 가 sizes.py 와 대조한다.
4. 회귀 검사       python scripts/test_skill.py <jobs.js>   (jsx 문법·ES3 함정·조각 이름·치수 검산·래스터효과 300)
5. 빌드            run.ps1 -Main "<메인.ai>" -Jobs <jobs.js> -Only <key>  → 한 항목 먼저 → preview.py 로 jpg → 보여 드리고 → -Only all

6. 검증            python scripts/preview.py → 눈으로 + references/design-quality.md 대조. 로그(C:\mvv\build_log.txt)의 '글자:' 줄에 옛 문구 0건, rgb_raster=0, 치수=검산값.

8. 출력(_출)       컨펌 뒤 간판 스킬 '8. 출력 파일 만들기' 절차: out_prep → render_signs(150ppi CMYK TIFF) → build_out(글자깨기·CS6·_출.jpg) → `발주\출력\`.

                   같은 이름 PNG 가 있으면 건너뛴다(--force 일 때만 덮어씀). 발주 시트는 맵이 아니다.
```

## B. 메인 교체 — 예전 바레이션이 이미 있을 때 (`scripts/swap_visual.jsx`)
- 메인비주얼만 새로 나오고 판 구성(사진·인물·문구·크기)은 그대로일 때. 사본(C:/mvv/hw)에서만 열고, 원본은 작업기록 폴더에 `백업_<이름>_<날짜>_수정전.ai` 후 같은 파일에 덮어쓴다. **발주\원본 과 map 폴더 둘 다** 고친다.
- 행사마다 파일 머리의 `CFG.mainPieces`(새 메인 조각 순번)·`CFG.match`(예전 제목·슬로건 글자)를 정한다.
- 찾는 규칙: **원(소용돌이)** = 불투명도<100 · 자식 2 · 첫 자식 묶음의 첫 조각이 지도 → 새 원의 지도 조각을 예전 지도 조각 높이·중심에 맞춘다(묶음 경계는 판 밖까지 퍼져 있으니 묶음 높이에 맞추지 않는다). 새 원에는 가운데 지도 조각을 꼭 포함. **제목** = [회차·영문 글자 묶음]+[붓글씨 복합패스] → 같은 폭·중심, 작은 제목(현수막·데스크·포토존 가로형)도 잡고 세로 제목은 제외. **슬로건** = 두 줄 모양일 때만(비율 0.6~1.6배) 교체 — 한 줄 자리에 두 줄을 넣으면 제목과 겹친다.
- 원 불투명도는 메인처럼 `swirlOpacity:100`. 글자·붓글씨와 겹치는 원만 `softenBehindText` 50%(35% 는 너무 흐림). 바탕은 메인과 같게(`whiteBg`: 판을 덮는 흰→크림 그라데이션은 흰색, 반투명 질감 이미지는 숨김). ASURA님이 만든 파일도 같은 규칙. 모음 대지는 `isSheet`(다른 대지 2개 이상 품음)로 가린다.
- 이어 붙이는 판(포토존 4m×2): `photozone8m.split:2`(판마다 3930) + `inPlace:true` 로 제자리에 펼치고 옆 사본은 지움. 큰 원은 이음매 가운데 90% 높이(사람이 서는 프레임), 제목 왼판 위·슬로건 오른판 위(머리선 1.8m 위). 바탕 밖 원은 클립(`polish` ④).
- `labels` 로 대지마다 왼쪽 위에 4줄 발주 라벨('이름 / 마감 / WxHmm / 수량'), 구역 제목은 라벨 왼쪽으로 비킴. 이미 새 원이 든 파일은 `labelOnly`.
- `polish()` — 납품 전 `references/design-quality.md` 대조 + 대지 걸친 글자 검사. 끝나면 대지 이름 그대로 map PNG(144ppi·투명), 모음 시트 대지는 뺀다.
- ExtendScript 전역 변수 이름 `name` 은 쓰지 않는다(파일 경로가 깨진다).

## C. 글자만 고치는 수정 요청 (`scripts/edit_text.jsx`)
- 대상 찾기: 발주 원본 .ai **와 `map` 폴더의 보조 .ai·텍스처 jpg/png** 까지 같은 글자를 전부 찾는다. 찾는 근거는 **일러가 실제로 여는 내용**(`exportFile` 렌더·textFrames) — pymupdf 미리보기와 다를 수 있다(이벤트.ai: 미리보기엔 날개 제목이 있는데 문서엔 없음). 라이브 텍스트가 없는 파일(글자가 그림·아웃라인)은 고칠 수 없다고 보고하고 사용자 결정을 받는다.
- 사본 `C:\mvv\<행사>\` 에 복사 → `C:/mvv/jsx/edit_cfg.js` 에 `EDIT = {files:[[열 파일, 저장 파일]…], find, replace, log}` → `run.ps1 -Jsx "<...>\edit_text.jsx"`. 글자를 빼는 수정(띄어쓰기 제거)은 그 글자만 `remove()` 해 서식이 그대로이고, 지우기 전 글상자 중심을 재서 `translate` 로 되돌린다(세로 날개 글자도 같음). 글자를 넣거나 바꾸는 수정은 서식이 앞 글자를 따르니 결과를 꼭 렌더로 본다.
- 텍스처 jpg: `C:/mvv/jsx/export_cfg.js` 에 `EXPORT = {outDir, ppi:150, jobs:[[파일, [[대지번호, 이름]…]]]}` → `run.ps1 -Jsx "<...>\export_jpg.jsx"` → `python scripts/map_jpg.py <새 폴더> <기존 jpg 폴더>` 로 기존 픽셀 크기에 맞춘 뒤(1px 차이 리샘플, 2% 넘으면 멈춤) 같은 이름으로 덮는다. 원본 .ai 에 없는 판인데 같은 디자인 jpg 가 있으면(날개) 그 jpg 를 복사한다.
- 검증: 수정 로그 `fixed=` 건수 = 인벤토리에서 찾은 건수, 수정 전후 렌더 나란히 비교(중심 어긋남 없음), 덮어쓴 파일 MD5 = 사본. 보고에 '고친 파일·곳 수 / 못 고친 파일과 이유 / 3ds Max 에서 재질 다시 읽기 필요' 를 적는다.

## LED 화면 (3D 맵용 — 발주 아님)
- 결과는 행사 `08 3D\map\`(또는 `01 3D\map\`)에 `.ai` + `.jpg`(긴 변 6000px, RGB). 시트·라벨·여유 없음(`sheet:false`). 기존 파일은 덮지 않는다.
- **두 판**(참고: 지식재산대전 2026 `제안/01 3D/map/무대LED.ai`): ① **기본** — 화면 전체 행사 비주얼(원·제목 가운데, Host·Organizer 로고 위 양쪽) ② **연사** — 연사는 LED 가운데 앞에 서고 **좌우에 그 연사를 찍은 카메라 화면 창(IMAG)**. 비주얼·배경은 판 전체에 이어지고 창은 테두리가 있는 별도 화면(창 배경 = 연사 뒤 LED 흐리게, 연사 상반신+포디움). 판을 셋으로 갈라 사람을 세우면 반려. 재료 `examples/inwepf_2026/make_led_assets.py`.
- **LED 픽셀 효과** — 참고 파일의 RGB 픽셀 줄무늬(1597x900)를 **Overlay 50%** 로 덮는다(7.29m 폭 타일). LED 는 **RGB 문서**(`rgb:true`) — CMYK 에서는 Overlay 가 다르게 보인다. step 에 `blend:"OVERLAY", op:50`.
- **배경은 디자인팀 가로 원본부터** — `02 소스` 에 16:9 단계별 PNG 가 있으면 '배경만'을 LED 비율로 아래 맞춰 자른다(`examples/inwepf_2026/make_bg.py`). 세로 포스터 풍경 묶음은 투명도 마스크가 걸려 떼어 오면 사라진다. 없을 때만 `scripts/wide_bg.py`.
- **연사 사진은 만들지 않는다** — 지식재산대전 `무대LED.ai` 의 배경 투명 연사+포디움 컷(사진 xref 99 + 마스크 xref 612, pymupdf `fitz.Pixmap(base, mask)`)을 재사용하고, 포디움 앞 회색 빈 판에 그 행사 포디움 폼보드 jpg 를 얹는다.
- 원·제목·국기·슬로건은 메인 벡터 조각을 **한 조각으로 묶어**(`items` 여러 개) 포스터 속 상대 위치 그대로. 날짜는 넣지 않는다.

## jobs.js 쓰는 법
- `PIECES["이름"] = { src:"main"|"<extra>", region:[x,y,w,h] (원본 대지 mm) 또는 items:[[레이어,순번,(묶음 안 순번)…]], scale: 원본 1mm = 실물 mm (1/10 시트 원본이면 10), minW, back:true(맨 뒤 하나 = 배경) }`
- `JOBS[]` = `{ key, event, title, file, W, H(발주 mm), bleed(불칼질 100), mat, pos, qty, shape:"circle", sheet:false, dest:"map", hold:"사유", layout:[step…] }`
- step = `{ img:"<tif>" | piece | pieces:[…], text, ptScale, maxW, mode:"row"|"col", gap, at:[x,y] + anchor:"tl|tr|bl|br|…" 또는 cx,cy, w 또는 h(비율 유지; 둘 다 주면 늘림), op, rot, flip, bg:true, fill:[c,m,y,k], blend, op }` — 좌표는 **보이는 면**(여유 안쪽) 좌상단 기준 실물 mm, 아래로 +. 순서 = 아래→위.
- 제목 3줄을 가로 한 줄로: `pieces:["제목1","제목2","제목3"], mode:"row"`. 측면 날개 세로쓰기: 같은 줄에 `rot:-90`(위→아래로 읽게).
- **새 도형·새 글자**(메인에 없는 것): `{ poly:[[x,y]…], open, fill, stroke, sw }` = 다각형·열린 선(sw 실물 mm). 이름 판은 **둥글게 하지 않는다** — 사내 관행은 모서리 45° 따기 + 위 가운데 홈(행사명 자리) + 청록 테두리 + 양끝 꺾쇠(부산 2026 `메인무대게이트.ai`) / `{ newText:"COMPANY NAME", font:[후보…], color:[c,m,y,k], cx, cy, h, maxW }` = 글자 높이 h(실물 mm)에 맞춰 크기 자동, 폭 넘으면 축소. 기관명 미정 자리 표시용.
- 본보기: `examples/chungnam_2026/jobs.js`(중앙백월·입구백월·측면·LED), `examples/inwepf_2026/`(무대 LED 10x4m 기본·연사, `jobs_booth.js` 부스 간판·켈지·날개).

## 함정 (실측)
1. **메인 .ai 의 PDF 층은 효과 글자를 그림으로 바꿔 둔다** — pymupdf 로는 제목이 글자 12개의 작은 이미지로 보인다. 조각 고르기는 일러(ExtendScript)로, pymupdf 는 위치 참고용.
2. **사용자가 일러에서 작업 중이면 COM 읽기가 멈춘다**(드래그·대화상자). 2분 넘게 안 돌아오면 끊고, 저장된 파일을 pymupdf 로 읽는다.
3. 시트 저장은 `C:/mvv/out` 짧은 경로(긴 한글 경로 saveAs Error 8700). 납품 때 복사.
4. 조각 복제는 벡터 그대로다. 반투명·스크린 겹침이 있는 조각(꽃)은 그룹 불투명도로 처리되면 괜찮지만, 겹침 모드가 안에 있으면 pymupdf CMYK TIFF 로 바꿔 넣는다.
5. ExtendScript 함정(겹친 삼항식·Array.indexOf·한 줄 `//` 주석·BOM 없는 한글 jsx·전역 `name`)은 `test_skill.py` 가 잡는다. jsx/js 는 **UTF-8 BOM**.
6. **그라데이션 재료는 `to_cmyk(..., flat_top=0)`** — 기본값은 넓은 단색 면을 최적값으로 덮어쓰는데, 세로 그라데이션은 줄마다 같은 색이라 이게 걸려 가로 띠가 생긴다.
7. 디자인팀 가로 배경에서 간판 띠를 자를 때는 산 능선 근처(INWEPF Y=2600/4500) — 아래(3250)는 밝아서 흰 행사명이 안 보인다.
8. **부스명이 확정되면 이름마다 파일 하나** — 같은 치수라도 이름이 다르면 `<파일>_1`, `_2`(부스 번호 순) 로 나누고 수량은 각 1. 부스 수가 바뀌면 켈지(부스당 1)·간판 수량도 같이. 쓸모없어진 옛 한 장짜리 파일(원본 .ai·jpg·맵 png)은 휴지통으로. 긴 영문 기관명은 `newText` 의 maxW 로 한 줄에(2930 판 30pt·1940 판 24pt 시트 기준).
9. **PowerShell 도구에 한글 경로를 직접 쓰면 깨진다** — Copy-Item 은 됐는데 Get-ChildItem·Test-Path 가 조용히 빈 결과. `X:\…` 한글 경로 파일 작업·확인은 bash 또는 Python(휴지통은 `SHFileOperationW` FO_DELETE+ALLOWUNDO) 으로. Python 은 `PYTHONUTF8=1`.
10. **Python 문자열 안 윈도우 경로의 `\0`·`\1`… 은 제어문자가 된다** — `"…\02 소스"` 의 `\02` 가 `\x02`. 경로는 `/` 로 쓰거나 Edit 도구로 직접 고친다.
11. **디자인팀 RGB 소스를 CMYK 로 바꾸면 남색 하늘이 메인 CMYK 와 다르게 나온다** — 소스 PNG 하늘(0,12,104)이 메인 CMYK(C100 M91 Y32 K53)보다 밝아 변환값이 C100 M100 Y51 K2(보라 기운). ICC 변환은 M100·Y60 아래로 안 내려간다 → **CMYK 로 바꾼 뒤 남색 픽셀만 직접 보정**: 가중치 w = (B 104 이하 1 ~ 140 이상 0) × (R 20 이하만), M·Y 는 목표(91·32)보다 클 때만 w 만큼 끌어내리고 K 는 53 으로 w 만큼. 원 안 보라·풍경은 안 건드린다. 메인 CMYK 값은 pymupdf `get_pixmap(colorspace=csCMYK)` 로 메인 .ai 하늘을 찍어 읽는다(`make_booth_assets.py`).
12. **새 시트 문서는 래스터효과 해상도 300ppi** — 일러 기본 72 로 두면 1/10 시트의 글로우·블러가 실물 7ppi 로 굳어 PDF 층·`_출` 렌더·맵 PNG 에 그대로 들어간다. 300 과 1500 은 결과가 같고 파일만 커서(1.1→10MB) 300 고정(build.jsx·order_sheet.jsx, `test_skill.py` 검사).
13. **pymupdf(PDF 미리보기) 렌더와 일러가 실제로 여는 내용이 다를 수 있다** — 고칠 대상·검증은 일러 `exportFile` 렌더로.
14. 일러 150ppi JPEG 내보내기는 기존 텍스처보다 1px 다를 수 있다 → `map_jpg.py` 로 기존 크기에 맞춘다. 같은 디자인 날개는 jpg 가 서로 같다(평균차 0.3 이하) — 복사로 대체 가능.

15. **묶음에 걸린 효과(드롭섀도·오프셋 외곽)는 스크립트로 못 끈다** — 조각을 효과 없는 새 묶음으로 옮기고(`move`) 옛 묶음을 지우면 효과가 같이 빠진다. 흰 스티커 외곽처럼 효과로 만든 모양이 사라지면 글자 사본에 흰 채움 + 둥근 흰 선(두께 = 외곽폭×2)으로 다시 만든다. 그림자가 빠지면 밝은 배경 위 흰 외곽은 테두리가 거의 안 보인다(정상, 순백 255 확인).
16. **캘리그라피 글자 정렬은 '가장 아래 삐침 끝'에 맞추지 않는다** — 붓 꼬리 끝에 맞추면 나머지 글자가 너무 내려가 어색하다. 긴 획이 있는 글자의 **몸통 밑선**을 기준으로, 나머지 글자는 서로의 리듬을 살려 **같은 양만큼 함께** 옮긴다.

17. **글자별 색을 바꾼 뒤에는 앞서 받아 둔 `textRange.characterAttributes` 참조가 무효**(Error 9503 illegal text range) — 크기 등은 `t.textRange.characterAttributes` 를 다시 얻어 바꾼다. 오류로 멈추면 사본이 일러에 열린 채 남으니 jsx 첫머리에서 `C:\mvv` 문서를 닫고 시작한다.
18. **바레이션은 항상 일러 빌더(.ai) 경로로 한다** — 맵 PNG만 달라고 해도 파이썬 PNG 합성으로 판을 짜지 않는다(KOBC 2026-11-03 반려 "바레이션 하던 대로 한겨"). 디자인팀 `03 소스` PNG 는 **배경·흰 로고 줄 같은 재료로만** img step 에 쓰고, 타이틀·날짜는 메인 .ai 벡터 조각.
19. **날개(300·500)에는 글자를 넣지 않는다** — 배경만. 굳이 넣으면 제목 한 줄 세로뿐("날개에 그리고 문구를 저렇게 많이 넣지 않어"). 날개는 본판과 한 장으로 배경을 만들어 잘라야 이어진다(가장자리 색을 늘리면 사진 판에 줄무늬).
20. **요청서에 없는 문구를 지어 넣지 않는다** — '1일차/2일차 확인해'는 일정 확인 지시이지 2일차 판·DAY2 문구를 만들라는 뜻이 아니었다. 애매하면 요청서 품목만 만든다.
21. **img 배경은 1mm=0.6px 안팎** — 8000x3000px(1mm=1px)로 넣었더니 스크린 내보내기에 가로 타일 이음매가 생겼다. 맵 2x 출력(0.567)보다 약간 촘촘하면 충분.
22. 메인 .ai 조각 번호는 probe 순서 그대로 다시 확인한다 — BMFW 본체 글자 묶음과 영문 머리글 TextFrame 순번을 바꿔 집어 옆가림막이 빈 윤곽선으로 나왔다. 조각만 단독으로 쓰는 판(작은 판)을 꼭 렌더로 본다.
23. **글꼴 대조를 빌드 전에 한다** — 메인 .ai 글꼴 목록(pymupdf `get_fonts`)을 설치 폰트와 대조해 빠진 게 있으면 먼저 알린다. 빠진 채 빌드하면 대체 글꼴로 굳는다(KOBC 2026-11-03: Poppins·평창체 없음, 사용자 "폰트도 없는데 어떻게 만든거야").
24. **"발주용"이면 sheet:false 를 쓰지 않는다** — 1/10 시트 + 라벨(재질/치수·수량/위치) + `발주\원본\<품목>.ai`·jpg. 맵만 달라는 말이 없으면 발주 시트가 기본("저거 왜 텍스트는 안들어가있어 사이즈랑?? 발주용으로 만들꺼라고").
25. **CMYK 판 기준이면 배경도 CMYK .ai 조각으로** — 03 소스 PNG 는 RGB 판에서 뽑은 것이라 색이 다르다(BMFW 평균차 19). 아주 가는 선이 수천 개인 장식(도시 7,695개 선)은 1/10 시트 벡터로 넣으면 맵 내보내기에서 사라지니 CMYK .ai 에서 그 조각만 투명 PNG(600%)로 뽑아 img 로 넣는다.
26. **발주 납품 = 그룹 시트 + 발주 PPTX** — 품목마다 따로 내지 않는다("등록데스크면 등록데스크 전부로 묶어 포토존이면 포토존 다 묶어서"). 그룹 = 등록데스크(백월·날개·앞판·가림막) / 포토존(본판·날개) / 메인무대 등. `scripts/group_order_sheet.jsx`(GROUPS·rows 만 고쳐 쓴다, 행사별 사본) → `발주\원본\<그룹>_발주.ai·jpg`, `scripts/order_pptx.py` → `발주\<행사>_발주.pptx`. 사용자가 그룹 시트를 직접 고쳤으면 맵은 그 시트 사본에서 `scripts/sheet_maps.jsx` 로 뽑는다(판 = 이름 있는 클리핑 그룹, 여유 10mm 잘라 2x). 양식 정본: 부산 2026 `4 현장설치물\★발주파일(공감)\부산 사이버보안_(공감발주).pptx` — 16:9, 표지(행사명 / 날짜 발주 / 담당자) + 그룹마다 그림 1장(그룹 이름 크게, 판 위 라벨 '이름 / 재질 / 마감 / 2930x500mm / 1ea').
27. **시트 바탕: 판이 흰색이면 회색(K25), 아니면 흰 바탕** — 흰 판을 흰 바탕에 두면 경계가 안 보인다(2026-11-03 "바레이션이 흰색이면 바탕은 회색이여 이거 이미 가르쳐줬잖아" — 양식 흰 바탕을 일괄 적용했다가 반려).
28. **날개(300) 기본 = 본판 색에 맞춘 부드러운 그라데이션 + 행사명(타이틀) 흐리게(25~30%) 세로** — 본판 그래픽을 이어 붙이지 않는다(잇는 건 사용자가 따로 말할 때만, "날개는 저렇게 그래픽 안이어지고 … 색상 맞춰서 슬로건이나 타이틀을 흐리게"). 사진 판의 줄별 평균색을 그대로 쓰면 층이 진다 — 높이 1/4 폭으로 흐려 쓴다("그라데이션 층생기잖아"). 슬로건이 아니라 행사명("슬로건 말고 그냥 행사명으로"). .ai 의 외형 효과 글자는 떼어 돌리면 안 보일 수 있다 → 디자인팀 한 줄 행사명 PNG 를 돌려 img 로.
29. **다른 문서로 판을 복제해 모을 때 위치는 복제 '뒤' 대상 문서에서 잰다** — 원본 문서 좌표로 이동량을 계산하면 눈금자 원점이 달라 판이 밀려 잘린다. 여유 표시처럼 함께 옮길 것은 원본에서 판과의 상대 위치만 잰다.
30. 요청서의 'Day 1/Day 2 행사명 반영'은 요청서에 적힌 그 문구(예: DAY1 KOBC BADA CONFERENCE / DAY2 …)를 판에 넣으라는 뜻이다 — 날짜별 판을 따로 만들라는 뜻이 아니다("1일차 2일차 저거 아녀?").
31. **사람이 서는 판(포토존·등록데스크 백월·로비 LED 목공)은 글자를 바닥 1,700 위에만** — 판 높이 3,000 이면 위 1,300, 백월 2,440 이면 위 740 안. 아래는 그래픽(도시 등)만("포토존 가운데 사람이 서면 170 위쪽으로 텍스트", 2026-11-03).
32. **이틀 행사면 행사명이 들어가는 판은 1일차/2일차 따로 만들어 그룹 파일 안에서 날짜별 줄로** — 공통 판(데스크·날개)은 '(두 날 공통)'으로 한 번만("1일차 2일차 나눠서 해야할꺼아녀", "같은 파일에 묶어서 확인하게"). 위계: 로고 줄(작게) → 타이틀(크게) → DAY 행사명 → 날짜·장소.
33. **요청서의 'LED + 목공(좌/우)'은 LED 양옆 목공판이고, 사용자가 따로 말한 날개는 그것과 별개로 추가**한다 — 하나로 합치거나 빼지 않는다(로비 LED: 목공 2,440 ×2 + 날개 500 ×2, "목공이랑 그옆에 날개 500 도 2개 같이 넣으라고").
34. **등록데스크 백월** = 큰 가로 로고타입 → 구역 이름판(흰 판·45° 따기·청록 테두리·남색 글자) → 아래 그래픽. 구역 글자를 맨 글자로 흩어 두면 "디자인 존나구려" 반려.
