## 0. 시작 전 (질문 없이 기본값으로)
- 요청서 **모든 장**을 PNG 로 렌더해 눈으로 본다. 텍스트만 뽑으면 판 구성(가운데 LED + 좌우 목공 등)을 놓친다.
- 메인 .ai 글꼴 대조(pymupdf `get_fonts` ↔ 설치 폰트). 빠진 글꼴이 있으면 **빌드 전에** 알린다("폰트도 없는데 어떻게 만든거야").
- 메인이 CMYK/RGB 두 판이면 **CMYK 판 기준**. 배경·그래픽도 CMYK .ai 조각("cmyk로 된걸로").
- 시공 방식이 없으면 묻지 말고 **목공 = 보이는 면 + 상하좌우 100** 으로 둔다("다 목공이야").
- 이틀 행사면 처음부터 **1일차/2일차 세트**로("1일차 2일차 나눠서 해야할꺼아녀").

## 1. 판 구성 읽기 — 요청서 그대로
- 'LED a×b + 목공(좌/우) c×d' = 가운데 LED(우리 몫 아님) 양옆 **목공판**. 사용자가 따로 말한 날개는 **별개로 추가**(합치거나 빼지 않는다, "목공이랑 그옆에 날개 500 도 2개 같이 넣으라고").
- '여기 하단에 로고 넣어주세요' 화살표 = 그 판(예: 무대 LED 아래 파란 목공판)에 **그 내용만**. 포스터처럼 채우지 않는다("무대하단 파란판이 목공이라고 거기에 넣으란데로").
- 'Day 1/Day 2 행사명 반영' = 요청서에 적힌 그 문구를 판에("1일차 2일차 저거 아녀?"). 문구를 지어내지 않는다.

## 2. 디자인 — 부산 발주본 방식
- **메인비주얼에 있는 것을 가져다 쓴다**(사본에서 벡터 조각 복제). 따로 PNG 를 뽑지 않는다("메인비주얼에 있는거 갓다 쓰라고", "자꾸 뭘 뽑아"). 예외: 도시·크레인처럼 **극세선 수천 개** 장식은 1/10 시트 벡터로 넣으면 jpg·맵에서 선이 사라져 판이 빈다("여기 이거 뭐냐고 왜 저따구로 그래픽을") → 메인 CMYK 사본에서 그 조각만 그림으로 굳혀(`kobc_city_png.jsx` 꼴) 넣고, **빌드 뒤 jpg 미리보기로 그래픽이 보이는지 반드시 확인**한다.
- 넓은 판: 메인 그래픽(도시·크레인·배)을 **판 폭 가득, 아래 기준**으로 크게. 가운데 작게 띄우지 않는다("저렇게 넓으면 메인에 있는거 활용좀 해서").
- 위계(위 1/3 한 덩어리): 타이틀(메인 타이틀 그대로, 흰 로고 대체 금지 "로고 왜 흰색인데") → DAY 행사명 → 날짜·장소 → **기관 로고 줄(타이틀 바로 밑, 타이틀 폭의 0.8)**. 로고를 맨 위에 작게 두지 않는다("기관 저렇게 상단에 조그만하게 안들어가").
- 사람이 서는 판(포토존·데스크 백월·로비 목공): 글자는 **바닥 1,700 위**에만. 판 3,000 → 위 1,300 / 백월 2,440 → 위 740("170 위쪽으로 텍스트").
- 같은 줄 구역 글자(Pre-registration / On-site / …)는 **같은 크기**(build.jsx `newText` 의 `sizeRef`, "텍스트 3개 비율 왜 틀려").
- 흰 이름판·물결선 과다·글자 흩뿌리기 금지("디자인 존나구려", "이거 너무 이상하다고").
- 날개(300~500): 본판 그래픽을 잇지 않는다 → 본판 색 **부드러운** 그라데이션 + **행사명** 흐리게(25~30%) 세로. 사진 판 줄별 평균색은 1/4 높이로 흐려 쓴다("그라데이션 층생기잖아", "슬로건 말고 그냥 행사명으로").

## 2-1. 추가 반려 (2026-11-03 저녁)
- **텍스트만 있는 판 금지** — 앞판·가림막·무대 하단판도 메인 도시·크레인을 **반투명(35%)**으로 깐다("배경에 뭔가 반투명으로 이미지 깔리게").
- **DAY 표시는 메인의 하늘색 캡슐 배지 + 행사명** — 맨 글자 한 줄 금지("데이 표시 그냥 텍스트만 있는게 아니잖아"). 메인 조각 그대로(배지 = 글자 조각을 위로, 캡슐 아래로 — 반대면 캡슐이 글자를 덮는다).
- **행사명이 들어가는 판은 모두 1일차/2일차 따로** — 무대 하단 목공판도("1일차 2일차 따로라고"). 그날 행사명만 **크게, 가운데**, 길면 두 줄("한줄찍 하면 뭐냐고").
- **구역 안내(등록데스크)는 간판처럼** — 같은 폭 판 3개·같은 간격·남색 판 + 하늘색 테두리 + 모서리 45° 따기, 흰 글자 크게(`sizeRef` 로 같은 크기). 흰 판·가는 선 구분·작은 맨 글자는 반려.
- **극세선 그래픽을 그림으로 굳힐 때 합성 모드(스크린·컬러닷지) 조각은 뺀다** — 투명 배경에 굳히면 빛기둥이 회색 얼룩이 된다("도시건물 배 얼룩지는건 뭐여").
- 좌·우 같은 디자인 날개는 **한 번만 놓고 2ea**("날개가 동일하면 갯수만 늘리면 되잖아").
- 그룹 시트에서 판 위치는 **클리핑 패스(판 외곽)**로 잰다 — 묶음 bounds 는 판 밖 그래픽까지 잡혀 판이 밀린다.

## 2-2. 사용자 직접 수정본에서 배운 것 (2026-11-03 밤)
- **주최 로고 4개 = 2개씩 판 상단 좌·우 끝에 작게**(폭의 ~13%). 타이틀 옆에 붙이거나 날짜 밑 한 줄로 두지 않는다("로고는 좌우측에 2개씩 상단에 위치 사이즈 좀 줄이고").
- **구역 안내 = 하늘색 캡슐(둥근 끝, C80 M5) + 흰 굵은 글자 크게**, 같은 폭·같은 간격. build.jsx `pill` step.
- **빈 공간 없이 크게** — 짧은 판(무대 하단 4,000×2,000)도 타이틀 폭 60%, DAY 배지·행사명을 키워 판을 채운다("빈공간이 너무 많지 않냐 … 텍스트 좀 더 크게").
- **세계지도 구·도시처럼 클리핑·불투명도가 여러 겹인 극세선 장식은 메인 CMYK 사본에서 그 조각만 그림으로 굳혀** 넣는다(`scripts/raster_piece.jsx` 꼴, 합성 모드 조각은 빼고). 벡터로 넣으면 1/10 판에서 표현되지 않는다("지구본 표현 안된다 … 원인 찾아서 고치라고").
- **보여 드리기 전에 자체 검수**: build.jsx 가 앞에 보이는 요소끼리 겹치면 로그에 `겹침:` 을 남긴다 → **0건이 아니면 고치고 다시 빌드**한 뒤에 보여 준다("내가 일일이 다 이렇게 체크하면 널 왜쓰냐고").
- **요청서에 적힌 요소 순서를 그대로 지킨다** — 'BMFW 타이틀 / Day 행사명 / 날짜+장소 / 로고' 면 위→아래 그 순서, 로고는 날짜 밑(상단 모서리로 빼지 않는다, "이거 순으로 넣으라고"). 상단 좌우 2개씩은 등록데스크처럼 사용자가 직접 그렇게 만든 판에만.
- **행사명(DAY 줄)은 강조** — 타이틀 아래에서 가장 큰 글자(포토존 220mm·로비 190mm 높이), 날짜는 작게("행사명 반영되있는건 강조를 좀 해주란거 아니냐").
- **캡슐 구역 안내 색 = 배경 남청(C100 M75 Y10 K15) + 흰 테두리**, 튀는 하늘색 단색 금지("색상 바꾸고 어울리게 테두리").
- **같은 디자인 날개는 판마다·날마다 반복하지 않고 시트에 한 번, 총수량**(예: BMFW 날개 6ea) — "날개 똑같으면 하나로 묶으라고 갯수만 체크하고".
- jobs.js 는 `test_skill.py` 가 node 로 실제 실행해 본다 — 줄 끝 주석이 쉼표를 먹어 일러에서 6판이 한꺼번에 실패한 적이 있다.
- **타이틀과 DAY 행사명 사이 ≈100mm(실물) 띄운다** — 붙으면 답답("행사명이 타이틀이랑 너무 붙어있어"). 블록 위계 간격: 타이틀 → 100 → DAY 줄 → 60 → 날짜 → 50 → 로고.
- **날개 흐린 글자는 날개 폭과 상관없이 같은 크기(폭 230)** — 500 날개만 키우면 투박하다.
- **이틀 행사 기본 = 한 판에 Day1·Day2 같이**(요청서 'Day 1 행사명 반영 / Day 2 행사명 반영' = 한 판에 두 줄). 날짜별 판 분리는 사용자가 명시할 때만(2026-11-03 밤 사용자 정정 "1일차 2일차 하나로 같이 들어가는거다").
- **DAY 줄 = 배지 + 영문 행사명, 두 줄 왼쪽 끝 맞춤**(가운데 각각 맞추면 들쭉날쭉), 좁은 판(<6,000)은 긴 행사명을 두 줄로 나누고 둘째 줄은 행사명 첫 글자에 들여 맞춘다. 글자는 배지 높이의 ~70%로 크게("텍스트 키워", "좌측 정렬로"). build.jsx `job.rows`(ROW:<id>:<순번>, grp, indent).
- **메인에 있는 문구(슬로건·날짜줄)는 다시 타이핑하지 말고 메인 글상자 조각을 그대로** 가져온다 — 내용이 같아도 글꼴(평창체)·색 강조(바다=하늘, 금융=연두)가 빠져 "텍스트가 이게 맞아?" 반려(2026-11-04). 새 문구만 newText.
- **구역 안내 띠는 영문만**(Pre-registration / On-site Registration / Speaker · VIP · Panelist) — 한글 보조줄 넣지 않는다("한글은 필요 없어", 2026-11-04).

- **보여 드리기 전 판마다 house-order-style.md 의 그 판 종류 줄을 옮겨 적고 대조**한다(예: 등록 하단 = "가운데 타이틀 + 그 밑 로고 작게"). 정본에 적어 놓고 앞판을 왼쪽 타이틀 | 로고로 만들어 "앞판도 행사명이 가운데로 … 너 디자인 학습한거 맞아" 반려(2026-11-04). 학습 문서는 읽기만 하면 소용없고 판마다 체크해야 한다.

- **등록데스크 최종(사용자 수정본 2026-11-04 11:25)에서 배운 것**: ① 백월 = 왼쪽 BMFW 타이틀(+로고) / 오른쪽 슬로건 두 줄을 **떨어뜨려** 양쪽에 둔다 — 세로선으로 붙인 타이틀|슬로건 덩어리는 사용자가 풀었다. ② 그래픽 배치를 메인 구도대로: 도시·크레인은 왼쪽 타이틀 아래로 흐리게 깔고, 오른쪽엔 지구본(항로선)+상승 차트, 슬로건은 지구본 위. ③ 앞판에도 오른쪽에 지구본을 넣어 왼쪽 도시와 균형. ④ 띠·구역 안내·날개(rot -90, 50%)·옆가림막은 B안 그대로 통과.
- **목공 불칼질 100 판의 하단(·상단) 띠 = 보이는 두께 + 100**: 판 끝 100mm는 접혀 안 보이므로(ㄱㄴ 바깥) 띠를 판 끝에 붙여 그리면 그만큼 얇아진다. 2026-11-04 앞판·옆가림막 띠 약 130mm → 3D에서 약 30mm 실선만 남음, 사용자 "하단 100 짤리면 띠가 얇게 들어갈텐데 맞어?". 띠는 ㄱㄴ 안쪽 기준으로 원하는 두께를 정하고 100을 더한다. 맵(PNG)이 곧 보이는 면이니 맵에서 띠 두께를 재서 확인한다. 적용(같은 날 "200 보이게 맞춰"): 띠 300(보임 200)으로 키우면서 띠에 덮이는 앞판 타이틀+로고는 90%로 줄여 띠 윗끝~보이는 윗끝(판 끝-100) 사이 가운데로 올렸다(위·아래 여백 70). 띠를 키울 땐 띠 윗선 아래로 내려오는 로고·글자를 먼저 확인한다. 함정: 사용자 스샷을 잴 때 판 가로세로 비율로 어느 판인지부터 맞춘다 — 앞판(7200×1250)을 백월(×2640)로 착각해 "백월에 저장 안 된 띠 280mm"라고 잘못 보고했다.
