## 정책 상수 (단일 진실 소스)
- **ARCHIVE_VISIBLE_LIMIT = 20** (2026-08-30 ASURA님 지시로 15 -> 20. 본문·코드의 모든 개수 판단은 이 값 하나만 따른다)
- 이 문서 어디에도 숫자를 다시 적지 않는다. 예전에 숫자가 문서 7곳·코드 5곳·사본 5벌에 흩어져 10과 15로 갈라진 적이 있다.
- 브리지 실행 경로의 짝은 `slack-claude-bridge/commands.py`의 `ARCHIVE_VISIBLE_LIMIT` 상수다. 한쪽만 바꾸면 검증 게이트가 정상 실행을 반려한다.
- 대상 DB: `collection://49d9582e-1be9-836d-a874-075f6db29687` (🔧 프로젝트) — 단일 워크스페이스이므로 하드코딩이 정답. 이름 검색으로 DB를 찾지 않는다.

## 목표
Notion 🔧 프로젝트 데이터베이스의 "A | 보관함" 그룹이 항상 최신 ARCHIVE_VISIBLE_LIMIT개 항목만 보이도록 자동 유지한다.

## 배경
- PARA 속성(select): "A | 보관함" 값을 가진 항목이 보드에서 보관함 그룹으로 표시됨
- 보관함_표시 속성(checkbox): 해당 항목이 보관함 소속인지 추적 (체크됨 = 보관함 소속)
- PARA = null이면 보드에서 숨겨짐 (보드 뷰는 PARA로 그룹핑하고 빈 그룹을 숨긴다)
- 보관연도 속성(select, 2026-09-30 추가): 보관 항목의 마감 연도. 통계 뷰 `🗄️ 연도별 보관 (통계)`(view://3eb9582e-1be9-81e9-9ded-000ca7de4a3d)가 이 값으로 그룹핑한다. 노션 뷰의 GROUP BY는 수식 속성을 지원하지 않아(조용히 무시) 수식이 아니라 실제 select로 둔다
- 정렬키 속성(formula): 보드 정렬용. 보관함만 마감일 내림차순, 나머지는 오름차순으로 만들어 한 보드에서 그룹별 순서가 다르게 보이게 한다. 지우면 보관함 순서가 뒤집힌다
- 규칙: 보관함 항목은 최신순으로 ARCHIVE_VISIBLE_LIMIT개만 PARA = "A | 보관함" 상태를 유지하고, 나머지는 PARA = null로 설정

## 실행 절차

### Step 1: 현재 보관함 소속 항목 전체 조회
**Notion 커넥터는 행 필터 쿼리가 불가하다 — 전체를 직접 읽고 로컬에서 분류한다.**
`notion-fetch`(또는 `notion-query-data-sources`)로 `collection://49d9582e-1be9-836d-a874-075f6db29687` 전체 행을 읽는다. 결과가 잘리면 이어서 끝까지 읽는다. `notion-search`를 속성 필터 용도로 쓰지 않는다.
읽은 전체 행에서 다음 두 그룹을 로컬로 분류:
- PARA = "A | 보관함" 인 항목 전체 (현재 보드에 표시 중인 보관함 항목)
- 보관함_표시가 체크됨이고 PARA = null인 항목 (이전에 숨겨진 보관함 항목)

전체 행 수와 분류 결과 수를 대조해 누락을 감지한다. 조회 실패 또는 0행이면 **아무것도 수정하지 말고 중단·보고한다.**
커넥터가 이어읽기를 지원하지 않아 전량 조회를 보장할 수 없으면 — 반환된 행 수를 보고에 명시하고 "전량 조회 미보장" 표시를 붙인 채 진행하되, 강등(PARA=null) 판단은 보수적으로(확실히 조회된 항목 안에서만) 한다.

### Step 2: 병합 및 정렬
두 그룹을 합쳐 "보관함 소속 전체 목록"을 만든다.
**정렬 키: `마감일`(date:마감일:start) 내림차순** — 최신 완료(마감) 순으로 위에 쌓인다. 마감일이 없는 카드는 항상 뒤로 보내고, 같은 마감일이면 제목 오름차순. (2026-09-30 ASURA님 지시. 이전 문서의 '생성일 기준'은 브리지 코드(`commands.py`의 보관함 프롬프트, 마감일 최근순)와 어긋난 오기였다 — 코드가 정본.)
`last_edited_time`·생성일은 쓰지 않는다: 이 스킬의 PARA 쓰기가 수정일을 갱신해, 강등한 항목이 다음 실행에서 최상위로 복귀하는 진동이 생긴다.

### Step 3: 상태 조정 (순차 실행)
- **신규 보관 항목 보호:** PARA = "A | 보관함"인데 보관함_표시가 아직 체크되지 않은 항목(= 방금 사용자가 보관함으로 옮긴 항목)은 생성일이 오래됐어도 **이번 실행에서는 순위와 무관하게 표시 대상에 우선 포함**한다 — "방금 보관했는데 바로 사라짐" 방지. 이때 표시 총량은 항상 ARCHIVE_VISIBLE_LIMIT개로 유지한다: 보호 항목이 들어온 수만큼 기존 표시분의 하위 순위(생성일 오래된 순)부터 한도 밖으로 밀려 함께 강등된다.
- 상위 ARCHIVE_VISIBLE_LIMIT위 항목: PARA = "A | 보관함", 보관함_표시 = "__YES__" 로 설정 (이미 설정된 경우 스킵)
- 그 아래 항목: PARA = null, 보관함_표시 = "__YES__" 로 설정 (이미 설정된 경우 스킵)

- **보관연도(select) 기록:** 모든 보관 후보(표시 중이든 숨겨졌든)에 그 후보 `마감일`의 연도(예: `2026`)를 `보관연도`로 쓴다. 마감일이 없으면 `연도 미상`. 새 연도 옵션이 없으면 그 이름으로 값을 쓰면 자동 생성된다. 이미 같은 값이면 쓰지 않는다. 숨겨진 항목이 이 값으로 `🗄️ 연도별 보관 (통계)` 뷰에 연도별로 모인다.

표기 규약: `notion-update-page`의 checkbox 쓰기 표기는 `"__YES__"`/`"__NO__"`(커넥터 공식 규약)이며, 조회 조건의 '체크됨'은 `__YES__` 상태를 뜻한다. select를 비울 때 `null` 전달은 '속성 값 제거'의 공식 규약이다.
**업데이트는 배치/병렬 금지 — 한 페이지씩 순차 실행하고, 각 호출 전 page id와 제목을 대조 확인한다** (배치 에이전트는 id를 뒤섞은 이력 있음). 429(rate limit) 응답 시 잠시 대기 후 그 항목만 1회 재시도.

### Step 4: 변경 사항 보고
변경 성공/스킵/실패를 분리해 항목 수와 목록을 간략히 출력한다. 실패가 1건이라도 있으면 "완료" 대신 실패 목록을 보고한다. 변경 없으면 "보관함 정상 (한도 이하)" 출력.

## 사용 도구
- Notion 커넥터의 `notion-search` / `notion-fetch` / `notion-query-data-sources` / `notion-update-page`
- (도구 접두사 `mcp__<서버id>__`는 세션마다 다를 수 있으므로, 현재 세션의 실제 Notion MCP 서버에서 확인해 사용한다)

## 주의사항
- 보관함_표시가 체크 안 됨(또는 null)이고 PARA = null인 항목은 보관함 소속이 아니므로 건드리지 않는다
- 보관함_표시/PARA 속성이 스키마에 없으면 임의 생성하지 말고 중단·보고한다 (fail-loud)
- 변경 시 최소한의 업데이트만 수행 (불필요한 API 호출 방지)
- 실행 주기: 브리지 루틴 `notion-bokhameham-weekly`가 **매일 21:37**에 돈다(이름의 weekly는 마커 파일명이라 그대로). 수동 실행은 '보관함 정리'.
