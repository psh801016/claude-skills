## 목표
노션 할 일 DB에서 프로젝트가 연결되어 있지만 "목표날짜"가 비어 있는 항목을 **빠짐없이** 찾아, 연결된 프로젝트의 "마감일"을 자동으로 채워 넣는다.

## 배경 정보 (DB id는 단일 워크스페이스 하드코딩이 정답 — 이름 검색으로 찾지 않는다)
- **할 일 DB** (data source): `collection://4709582e-1be9-8332-903b-87ce7db219fb`
- **프로젝트 DB** (data source): `collection://49d9582e-1be9-836d-a874-075f6db29687`
- 할 일의 **"목표날짜"** 필드에 날짜가 있어야 캘린더(세부 업무 뷰)에 표시됨
- 할 일의 **"프로젝트"** 필드는 프로젝트 DB와의 relation
- 프로젝트의 **"마감일"** 필드가 행사일/납기일 기준

## 실행 절차

### Step 1: 할 일 전량 조회 (부분 조회 금지)
**Notion 커넥터는 행 필터 쿼리가 불가하다 — 전체를 읽고 로컬에서 조건을 거른다.**
`notion-query-data-sources`(가능하면 우선) 또는 `notion-fetch`로 할 일 DB `collection://4709582e-1be9-8332-903b-87ce7db219fb` 전체 행을 읽는다.
- 결과가 잘리거나 페이지 크기에 도달하면 **커서/이어읽기로 소진될 때까지 반복 조회**한다. 단일 호출 결과만으로 판단을 종료하지 않는다.
- `notion-search`를 쓰는 경우에도 `data_source_url`로 범위를 한정하고, 반환 건수가 page_size에 도달하면 반드시 다음 페이지를 이어 읽는다.
- 전량 조회가 확인되지 않으면 아래 완료 문구("모든 할 일에…")를 절대 쓰지 않는다.
- 커넥터가 이어읽기를 지원하지 않아 전량 조회를 보장할 수 없으면 — 반환된 행 수를 보고에 명시하고 "전량 조회 미보장, 이번 실행은 조회된 N건만 처리" 표시를 붙인 채 진행한다(무한 재시도 금지).
- **조회 자체가 실패(도구 오류)하거나 0행이면** 어떤 쓰기도 하지 않고 실패/0행 사실을 보고하고 중단한다(fail-loud — 무음 통과 금지).

### Step 2: 각 항목 확인
조회된 전체 항목에서 다음 조건을 로컬로 거른다 (필요 시 `notion-fetch`로 개별 확인):
- `date:목표날짜:start`가 비어 있음 (null 또는 미설정)
- `프로젝트` relation에 연결된 프로젝트 URL이 1개 이상 있음
- 상태(상태)가 "완료" 또는 "취소"가 아님

### Step 3: 프로젝트 마감일 가져오기
조건을 만족하는 항목마다:
1. `프로젝트` 필드에서 연결된 프로젝트 페이지 URL 추출
2. `notion-fetch`로 해당 프로젝트 페이지 열기
3. 프로젝트의 `date:마감일:start` 및 `date:마감일:end` 값 확인
- **프로젝트가 2개 이상 연결된 경우**: 마감일이 있는 프로젝트 중 **가장 이른 마감일**을 사용한다(캘린더에 먼저 도래하는 일정 기준). 모든 연결 프로젝트에 마감일이 없으면 건너뛰고 보고에 사유를 남긴다.

### Step 4: 목표날짜 업데이트
프로젝트에 마감일이 있으면 `notion-update-page`로 할 일 항목의 목표날짜를 설정:
- command: `update_properties`
- `date:목표날짜:start`: 프로젝트의 `date:마감일:start` 값
- `date:목표날짜:end`: 프로젝트의 `date:마감일:end` 값 (있을 경우만)
- `date:목표날짜:is_datetime`: **0 고정** (종일 이벤트). 마감일에 시간 성분이 있어도 날짜만 복사한다 — 시간 포함(1) 전환은 캘린더 뷰에서 시각·타임존·종일항목 혼합 정렬을 실측 검증하기 전까지 금지(미검증 의미론 변경은 하루 밀림 등 무음 오류 위험). 시간 성분을 버린 경우 보고에 "시간 성분 생략 N건"으로 명시한다(fail-loud).

업데이트는 한 항목씩 순차 실행. 429(rate limit) 응답 시 잠시 대기 후 그 항목만 1회 재시도.

### Step 5: 완료 보고
**성공 / 스킵(사유별) / 실패를 분리해** 항목 수와 이름을 보고한다.
- 실패가 1건이라도 있으면 "완료"라고 하지 않고 실패 목록을 보고한다.
- 전량 조회가 확인되고 변경이 없을 때만 "모든 할 일에 목표날짜가 설정되어 있습니다."라고 출력한다.

## 주의사항
- 이미 목표날짜가 설정된 항목은 건드리지 않는다
- 프로젝트에 마감일이 없는 경우 해당 할 일은 건너뛴다 (보고에 포함)
- 상태가 "완료" 또는 "취소"인 항목은 건너뛴다
- `보관함_표시`가 체크된 프로젝트 항목도 처리한다 (보관 여부와 무관하게 할 일에 날짜가 필요할 수 있음)
