# 전시·행사 조명 워크플로 및 출력 계약

이 문서는 `SKILL.md`의 보조 설명이다. 실행 규칙의 정본은 같은 폴더의 `SKILL.md`다.

## 입력 판단

- 조명 참고이미지가 있으면 빛의 수, 색온도, 광원 방향, 헤이즈 밀도, 빔 가장자리, 착지 반응, 간접광 범위, 분위기만 추출한다. 참고 이미지의 공간·가구·스크린·사람·그래픽은 절대 이식하지 않는다.
- 참고이미지가 없으면 원본의 실제 조명기구, 행사 종류, 무대·스크린 밝기, 실내 기본 조도, 테이블 배치, 반사 가능한 표면에서 자연스러운 설계를 도출한다. 빔 수는 공간이 결정하며 고정값을 쓰지 않는다.

## 이미지 제작 순서

1. 원본·선택본을 보존하고 요청의 조명 강도와 주변 노출을 기록한다. 사용자 요청이 기본 저헤이즈 설정보다 우선한다. 생성 도구가 정확한 조명 분리를 보장하지 못하면 전체 생성본은 후보로만 다룬다.
2. 원본 구조와 그래픽을 유지한 베이스를 만든다. 주변을 어둡게 하라는 요청은 베이스 노출에서 처리한다. 조명판의 검정 픽셀이나 Add/Screen으로 주변을 어둡게 만들 수 없다.
3. **베이스 → 표면 수광/반사 → 원본 그래픽 복원 → 앞 공간의 빔·헤이즈** 순서로 합성한다. LED 표면에 조명을 쏘지 않는 것과 카메라에 보이는 LED 앞 공기를 지우는 것은 다르다. 그래픽 복원 마스크를 앞 공간 레이어에 적용하지 않는다.
4. 실제 사용한 조명 레이어를 보존한다. 원본/선택본 해시, 광원·경로·착지·수광체, 앞 공간 효과, 비조명 영역과 합성 모드를 기록한다. 선택본이 바뀌면 경로와 해시도 갱신한다. 하나의 생성본에서 빔을 다시 그려 조명판만 만들지 않는다.
5. 동일 레이어에서 최종 합성본과 검정 배경 조명판을 각각 저장한다. 한 가지 합성 모드와 픽셀 연산을 기록한다. Add와 Screen을 임의로 바꾸지 않는다. 아래 검사를 저장된 파일에 실행하고, 원본 50% 오버레이와 조명판을 육안 대조한다.

**정확한 추출을 보장할 수 없는 평면 이미지:** `max(생성본−원본, 0)` 또는 블러는 구조·글자 잔여물과 잘린 하이라이트를 해결하지 못한다. 대응 조명 레이어/AOV나 검증 가능한 차이가 없으면 정확한 추출이라고 납품하지 않는다. 사용자가 효과 수정을 요청해 다시 만든 경우에는 재구성이라고 명시한다.

## 저장 파일 검증

`scripts/verify_light_pair.py`는 Pillow·NumPy를 사용한다. 기존 환경의 라이브러리를 재사용한다. 파일 경로는 아래 JSON 파일을 기준으로 해석한다.

```json
{
  "canvas": [2560, 1440],
  "mode": "screen",
  "base": "base.png",
  "composite": "final.png",
  "plate": "light-only.png",
  "source_layers": ["retained-light-layer.png"],
  "sha256": {
    "base.png": "ACTUAL_SHA256_OF_RETAINED_BASE",
    "retained-light-layer.png": "ACTUAL_SHA256_OF_RETAINED_LAYER",
    "expected-led-haze-support.png": "ACTUAL_SHA256_OF_PLANNED_SUPPORT",
    "expected-stage-support.png": "ACTUAL_SHA256_OF_PLANNED_SUPPORT",
    "expected-unlit.png": "ACTUAL_SHA256_OF_PLANNED_UNLIT_MASK"
  },
  "required_effects": [
    {"name": "LED foreground haze", "mask": "expected-led-haze-support.png", "min_value": 8},
    {"name": "stage response", "mask": "expected-stage-support.png"}
  ],
  "unlit_mask": "expected-unlit.png"
}
```

- `base.png`는 원본 그래픽을 복원하고 실제 합성에 사용한 베이스다. 원본과 노출이 다르면 재현에 필요한 베이스도 전달한다.
- `source_layers`는 출력 조명판과 별도로 보존한 실제 제작 레이어다. 동일 모드로 아래에서 위로 합친다. 서로 다른 블렌드·불투명도를 썼다면 먼저 실제 조명 성분으로 평탄화해 그 파일을 보존한다. 임의로 출력 조명판을 다시 복사해 제작 레이어라고 주장하지 않는다.
- 각 해시는 실제 파일 바이트의 SHA256으로 채운다. 합성에 쓰기 전에 베이스·레이어·판정 마스크를 잠그고 해시를 남긴다. 검사를 통과하려고 마스크를 축소/비워 바꾸면 실패해야 한다. 검증기는 전달 파일의 해시도 계산해 출력한다.
- 마스크는 원본 크기의 흑백 이진 PNG다. 흰 픽셀은 **실제로 효과가 있어야 하는 지원 영역** 또는 **비조명 영역**이다. 광원·수광체와 선택본에서 독립적으로 지정한다. 조명판의 밝은 픽셀을 그대로 마스크로 쓰면 누락 검사가 무의미하다. 사각형 전체를 빔 지원 영역으로 쓰지 말고 차광·감쇠를 반영한다. LED 앞 헤이즈가 있거나 요청됐으면 그 지원 영역도 반드시 검사한다.
- `min_value`는 지원 영역에서 필요한 최소 최대채널 값(1~255, 기본 1)이다. 시인성이 필요한 빔/헤이즈는 선택된 설계의 밝기에 맞춰 미리 정한다. 미세한 잔여 픽셀로 효과가 보존됐다고 통과시키지 않는다. 이 값도 물리적 정확성·출처의 증명은 아니다. 해시 일치는 보존 파일의 동일성을 확인할 뿐, 사후 복사본을 실제 제작 원본으로 바꿔주지 않는다.
- 검증 연산은 불투명 8bit RGB 기준 `add = min(255, base + plate)`, `screen = base + (255-base)*plate//255`이며 최대 채널 오차 1만 허용한다. 다른 색공간·블렌드 파이프라인이면 그에 맞는 검사를 사용하고 이 검사의 성공으로 대체하지 않는다.

```text
python scripts/verify_light_pair.py <pair.json>
python scripts/test_verify_light_pair.py
```

실제 exit 0과 `NUMERIC_PASS`만 수치 검사 성공이다. LED 누락·비조명 잔여물·독립 리사이즈·레이어 불일치·합성 불일치는 exit 1이다. 숫자가 통과해도 조명판의 글자/구조 흔적, 화면 경계에서 끊긴 빛, 광원과 착지 위치는 육안 검사해야 한다. 생성된 성공 문구나 동일 계산식의 자기 비교를 검증 근거로 쓰지 않는다.

기존 승인본의 일부를 고칠 때는 합성본과 조명판 각각의 수정 전 사본에 대해 `python scripts/verify_incremental_edit.py <backup> <candidate> --box X Y W H`도 실행한다. 허용 영역 밖 변경 픽셀은 0이어야 한다. 영역은 사용자 표시 또는 요청된 효과의 범위로 정하며 검사를 통과하려고 전체 캔버스로 늘리지 않는다. 수치 조명쌍 검사만으로 기존 효과 보존을 주장하지 않는다.

## 출력 계약

- 프롬프트 요청은 본문의 독립 블록 두 개만 제공한다.
- 이미지 요청은 최종 합성본과 그 제작 레이어에서 나온 조명판을 각각 표시하고 각각 클릭 가능한 **절대경로**로 전달한다. 베이스가 변경됐으면 합성 모드와 함께 재현용 베이스도 전달한다.
- 실제 치수·저장 경로·수치 검사 결과와 시각 검사 범위를 구분해서 보고한다. 작은 엔진 출력을 등록했다면 원래 크기를 숨기지 않는다. 실측 크기가 맞아도 모든 효과가 들어갔다는 뜻은 아니다.

## 다른 스킬과의 경계

- `interior-prompt-maker`: 재질 실사화와 구조 보존 베이스만 담당한다.
- `magnific-compositing-prep`: 선택된 합성본의 기하·선명도만 다루며 라이트 플레이트를 재처리하지 않는다.
- `person-layer-maker`: 선택된 조명 합성본에 사람만 맞추며 조명 설계를 바꾸지 않는다.
