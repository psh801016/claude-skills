# 아이소뷰 실사 인물 합성

## 절대 규칙

- 원본 구조, 벽체, 명화, 외벽 LED, 카메라, 캔버스 크기, 배경 알파는 수정하지 않는다.
- 전체 장면 i2i 결과는 최종본으로 사용하지 않는다. AI 생성물은 **인물/효과 후보 레이어**로만 사용하고, 최종은 원본 위 레이어 합성으로 만든다.
- 검정 배경을 새로 만들거나 불투명하게 채우지 않는다. 원본 알파 채널은 출력에서 바이트 단위로 동일해야 한다.
- 인물은 통행 가능한 바닥에만 둔다. 벽체·중앙 폐쇄공간·외벽 LED·명화 앞·통로 밖에는 배치하지 않는다.
- 인물의 발은 바닥에 접지되고, 벽/가구 뒤에 가려져야 할 부분은 마스크로 가린다. 접지 그림자는 인물 레이어 안의 작은 국부 그림자만 허용한다.

## ★ as-built 실사 규칙 — 전시·행사 장면이면 필수 (2026-09-21 배선)

원본이 **전시부스·행사장·등록데스크·포토존·백월**이면 기준물을 찾기 전에 읽는다:

```

```

**사본을 만들지 않는다 — 이 경로 하나만 본다.**

아이소 합성에서 특히 걸리는 것: **기준물 실측이 그 문서에 있다** — 연회의자 등받이 ≈950 ·
테이블 상판 ≈720 · 등록 백월 ≈2,480 · 옥타 폴 2,480 · 카운터·상담테이블 1,000.
그리고 **발광 부재(맥시마) 앞 인물은 시안-블루가 얹히고 바닥 색도 물들어 있다** —
인물만 중성색으로 두면 붕 뜬다.

## 기준 스케일

### 기본 절차 — 막대를 기다리지 말고 먼저 그려 확인받는다 (★ 사용자 지시 2026-09-01)

치수 아는 수직 요소(옥타 폴 2,480 등)를 서로 다른 두 깊이에서 찾아
`person-layer-maker/scripts/scale_bars.py` 로 스케일 필드를 계산하고 막대 오버레이를 만들어
**"이 스케일 맞습니까?"** 로 확인받는다. **O면 그대로, X면 ASURA님이 고쳐 주신 막대가 정본**이다.
아이소·정사영이면 상단선·하단선이 평행해 스크립트가 거부한다 — 그때는 깊이 축소 없이
아래 45–50% 환산을 쓰거나 막대를 요청한다. 절차 전문은 `person-layer-maker` C-0-2 절.

### 0순위 — 붉은 세로 막대가 있으면 계산하지 않는다 (★ 사용자 지시 2026-09-01)

ASURA님이 이미지에 **붉은 세로 막대**를 그려 주시면 그것은 **그 위치에서의 화면상 인물 높이 기준자**다.
**아래끝 = 발 접지점 · 위끝 = 머리끝 · 길이 = 그 위치에서의 전신 높이.**
목적은 **원본의 소실점·카메라 각도 때문에 위치마다 달라지는 스케일 감을 잡는 것**이므로
**막대 개수는 인물 수가 아니다**(앞·중간·뒤 기준자일 수 있다). 길이가 서로 다른 것은 원근이니
**평균 내거나 통일하지 않는다.** 굵기는 의미가 없다. 막대 없는 위치는
`h = k × (y_발 − y_수평선)` 로 보간한다(막대 2개면 풀리고 3개면 검산된다).
**아이소·정사영이면 막대 길이가 거의 같게 오며, 그때는 깊이 축소를 넣지 않는다.**
아래 1~4의 옥타 환산은 **막대가 없을 때의 기준**이다.
프롬프트에 `no red bars, no vertical markers in the result`를 넣고, 결과 위에 막대를 다시 얹어
머리끝·발끝이 **±5% 이내**인지 검수한다. 어긋나면 인물 레이어만 보정한다(전체 재생성 금지).
전문은 `references/photozone-placement-rules.md`의 '붉은 세로 막대' 절.

### 막대가 없을 때의 환산

1. 이미지 안의 내부 옥타 부스 수직 높이 `H_px`를 찾는다. 기본 실측 기준은 **2,500 mm**다.
2. 아이소메트릭 전시 렌더의 기본 성인 표시 높이는 **옥타 2,500 mm 수직 패널의 45–50%**(`H_px × 0.45–0.50`)로 잡는다. 이는 원근이 압축된 탑다운/아이소 뷰의 시각 기준이며, 실제 신장 1,700 mm를 화면 높이로 기계적으로 환산하지 않는다.
3. 사용자가 승인한 기준 이미지가 있으면 그 이미지의 인물 높이를 최우선 기준으로 삼는다. 기준 이미지가 없을 때만 `0.45–0.50 × H_px`를 사용하며, 그 범위를 넘는 인물은 거인처럼 보이는 오류로 반려한다.
4. 외곽 큐브 전체 높이는 프로젝트별로 달라도 옥타 2,500 mm가 보이면 그것을 최우선 기준으로 쓴다.

`scripts/calibrate_isometric_scale.py`로 계산값을 기록한다. 옥타 기준이 전혀 보이지 않으면 임의 수치를 쓰지 말고 사용자에게 기준 부재를 알린다.

## 실행 순서

1. `scripts/inspect_rgba_source.py <source>`로 PNG 모드·크기·알파·SHA-256을 기록한다.
2. 원본을 보기 전용으로 잠그고, 접근 가능한 바닥만 허용 마스크로 만든다. 이미지 전역을 허용하지 않는다.
3. 원근과 위에서 내려다보는 시점에 맞는 실사 인물만 별도 RGBA 레이어로 만든다. 기본은 3–6명이며, 요청이 없으면 통로를 막지 않도록 듬성듬성 배치한다.
   - **위치·방향이 중요하면 마커 오버레이를 쓴다(2026-08-25).** 원본 위 새 레이어에 형광색으로 점 = 각 인물 발 접지점, 화살표 = 그 인물이 향할 방향을 그려 별도 PNG로 저장하고, 원본과 함께 2장으로 넣는다. 프롬프트에는 `the [색] dots are where each person stands, the [색] arrows are the direction each person faces` 처럼 색으로 지칭하고 `no markers, no dots, no arrows in the result`를 넣는다. 대충 그려도 통과하며, **장면에 없는 형광색**을 써야 한다. **붉은 세로 막대가 함께 있으면 그것은 각 인물의 화면상 키다**(위 '기준 스케일 0순위'). 상세 규격은 `person-layer-maker` C-0·C-0-1 절이 정본이다.
4. 사람의 키는 **붉은 세로 막대가 있으면 막대 길이 그대로** 맞춘다. 막대가 없을 때만 옥타 2,500 mm
   기준으로 계산하고, 같은 통로 안에서도 먼 곳은 조금 작게 보정한다.
5. `scripts/composite_rgba.py`로 인물 레이어만 원본 위에 합성한다. 원본 알파는 그대로 되돌린다.
6. `scripts/verify_source_lock.py`로 허용 마스크 밖 RGB 변경이 0이고 전체 알파가 원본과 동일한지 확인한다. 하나라도 실패하면 출력물을 폐기한다.

## 스마트 글라스/홀로그램이 함께 있을 때

- 명화는 기존 내부 벽체에 이미 붙은 경우에만 사용한다. 외벽 LED와 원본 명화 픽셀은 건드리지 않는다.
- 명화 관람 장면에서는 각 인물을 가장 가까운 **벽체 부착 액자 명화** 쪽으로 배치한다. 고개·어깨·발끝이 액자 방향을 향해야 하며, 빈 벽을 향해 서 있거나 액자와 무관한 방향을 보는 인물은 반려한다. 인물은 실제 촬영 인물의 피부·머리카락·의복 질감으로 만들며 3D 캐릭터·미니어처·CGI 인형처럼 보이면 반려한다.
- 홀로그램은 명화 전면을 가리지 않는 옆/앞의 공중에, 반투명 선·입자·깊이감 있는 3D 형태로 한정한다.
- 홀로그램도 별도 RGBA 레이어로 만들고 인물 레이어와 동일하게 허용 마스크 검증을 통과해야 한다.

## 필수 검증

```powershell
python scripts/inspect_rgba_source.py <source.png>
python scripts/calibrate_isometric_scale.py --octa-px <measured> --adult-mm 1200
python scripts/composite_rgba.py --source <source.png> --layer <people.png> --mask <allowed.png> --output <final.png>
python scripts/verify_source_lock.py --source <source.png> --output <final.png> --allowed-mask <allowed.png>
```

통과 조건은 `ALPHA_EXACT=True`, `OUTSIDE_CHANGED_PIXELS=0`, 원본과 동일한 캔버스 크기다.

## 산출물

- 원본은 절대 덮어쓰지 않는다.
- 최종 PNG와 `*_people_layer.png`, `*_allowed_mask.png`, 검증 JSON을 별도 저장한다.
- 최종 보고에는 인원 수, 2,500 mm 기준에 따른 계산 키, SHA-256, 알파/구조 검증 결과를 함께 적는다.
