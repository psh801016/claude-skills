# Notion 업무일지 업로드 (보드 기반)

## 핵심 원칙

**다이어리 목록은 🔧프로젝트 보드가 마스터다.** (2026-06-30 사용자 지시)
보드의 `PARA` 속성으로 분류한다: `P | 현재 진행` = **제안디자인**, `A | 상시 진행` = **실행디자인**.
오늘자 일지 페이지가 이미 있으면 그 페이지를 **갱신**(복제 금지), 없으면 **오늘 이전 가장 최근 일지 페이지**를 복제해 인라인 DB 블록 구조를 유지한다.
**빈/틀린 일지는 절대 업로드하지 않는다** — 보드를 못 읽으면 중단하고 보고한다.
**보드는 읽기 전용 소스다** — 일지에 없는 활성 항목을 보드에서 자동 제거/PARA 변경하는 것은 절대 금지. 제거는 사용자 지시 + 3중검수 통과 시에만. (2026-06-30 사용자 확정 규칙)
**모든 날짜·요일은 Asia/Seoul(KST) 기준으로 계산한다.**

자동화: Hermes Slack 브리지가 **평일(월~금) 오전 8시**(2026-09-21 ASURA님 지시로 9시→8시)에 이 방식으로 자동 업로드한다(`slack-claude-bridge` server.py briefing_scheduler + commands.py run_diary). 수동 호출도 동일 절차(수동 호출은 요청 시점의 실제 오늘 날짜로 생성).

## 실행 순서

### 1단계: 🔧프로젝트 보드 조회 (정답 소스)
`notion-query-data-sources`로 '🔧 프로젝트' 데이터소스 `collection://49d9582e-1be9-836d-a874-075f6db29687`를 조회한다.
- `PARA = 'P | 현재 진행'` → 제안디자인
- `PARA = 'A | 상시 진행'` → 실행디자인
- 순서: **제안디자인 전체 먼저, 그다음 실행디자인 전체.** 각 그룹 내부는 `마감일(date:마감일:start)` 빠른 순, 없으면 뒤로.
- `R | 관심분야` / `A | 보관함` / 빈 PARA는 제외.

**보드 조회가 실패하거나 제안+실행 합이 0건이면 — 어떤 페이지도 만들거나 수정하지 말고 그 사실을 보고하고 중단한다.** (틀리거나 빈 일지를 올리느니 멈춘다. 추측·환각으로 목록 채우기 금지.)

### 2단계: 오늘자 페이지 확인 (멱등)
캘린더 DB `collection://8b39582e-1be9-8381-9d46-07c2fc5343e4`에서 **제목이 정확히 `MM/DD:`(오늘)이고 `date:날짜:start`가 오늘(`YYYY-MM-DD`)인** 페이지가 이미 있는지 확인한다.
- **있으면**: 복제하지 말고 그 페이지를 대상으로 3단계 수행 (중복 페이지 생성 금지). 조건에 맞는 페이지가 **여러 개면 중단**하고 중복 정리를 요청한다. 제목은 오늘 `MM/DD:`인데 `date:날짜`가 비었거나 다른 페이지가 발견되면 — 복제로 새로 만들지 말고 중단·보고한다(중복 생성 위험).
- **없으면**: 오늘 이전 **가장 최근** 일지를 복제한다. 최신 판별은 `date:날짜` 속성 기준(제목 `MM/DD:` 문자열 정렬 금지 — 연말·연초 경계에서 12/31이 01/02보다 크게 정렬되는 오류). `date:날짜`가 비어 있는 페이지는 `createdTime`(생성일)으로 대체 판별한다. `notion-duplicate-page`로 복제 후, 비동기일 수 있으니 새 페이지를 `notion-fetch`로 열어 `다이어리`·인라인 블록 복사를 확인한다(비면 15초 간격 최대 3회 재확인). **3회 후에도 비어 있으면 3단계로 진행하지 말고 복제본 상태(page_id 포함)를 보고하며 중단한다.** 복제본만 수정한다.
- **복제할 과거 일지가 하나도 없으면(첫 실행 등) 아무것도 만들지 말고 중단·보고한다.** `notion-create-pages`로 새로 만들지 않는다(인라인 DB 구조 누락).

### 3단계: 속성 동시 업데이트 (한 번의 update_properties)
대상 페이지 page_id에 `notion-update-page`(update_properties)를 **한 번만** 호출해 동시에:
- `date:날짜:start` = 오늘 `YYYY-MM-DD`
- `date:날짜:is_datetime` = 0
- `캘린더` = `MM/DD:`
- `다이어리` = 1단계 보드 목록:
  `MM.DD (요일)<br>1. <프로젝트명> : 제안디자인<br>2. <프로젝트명> : 실행디자인<br>...`
  (1번부터 제안 전체, 이어서 실행 전체. 번호 연속, 구분자 `<br>`. **요일은 암산 금지 — 코드로 계산해 주입한다**: 수동 실행 시 `Get-Date -Format "MM.dd (ddd)"` 등 도구 계산 값 사용, 브리지 자동화는 Python이 주입(동일 원칙). 한 글자 표기.)
  완성 예시: `07.03 (금)<br>1. 2026 세계 토양의 날 기념행사 : 제안디자인<br>2. BOK지역경제심포지엄 : 실행디자인`
  (제목 `MM/DD:`와 다이어리 헤더 `MM.DD`의 구분자 차이는 기존 Notion 관례 — 의도된 표기다.)

### 4단계: 완료 보고
보고 첫 줄은 브리지 자동화와 동일한 게이트 형식으로 시작한다: `DIARY_OK <페이지 URL> | 제안 N / 실행 M` (N+M≥1일 때만 — 아니면 성공 보고 금지). 이어서 갱신/복제 여부를 간결히 덧붙인다. 중단 시에는 `DIARY_ABORT <사유>`로 보고한다 — **올릴 항목이 0건인 정당한 무작업도 억지로 채우지 말고 `DIARY_ABORT 보드 활성항목 0건`으로 보고한다.**

## 자주 하는 실수 (하지 말 것)
- 보드를 안 읽고 전날 항목을 그대로 복사 → **구 방식. 이제 보드에서 생성한다.**
- 보드 조회 실패인데 빈 목록으로 업로드 → **절대 금지. 중단·보고.**
- 오늘자 페이지가 있는데 또 복제 → 중복 페이지. **있으면 갱신.**
- `다이어리` 속성을 빠뜨리고 날짜/캘린더만 업데이트.
- `notion-create-pages`로 새 페이지 생성 → 인라인 DB 구조 누락. (오늘자가 없을 때만 duplicate)
- 일지에 없는 활성 항목을 보드에서 자동 제거 → **절대 금지. 보드는 읽기 전용.**
- 제목 문자열로 '가장 최근' 판별 → **`date:날짜` 속성 기준으로 판별.**
