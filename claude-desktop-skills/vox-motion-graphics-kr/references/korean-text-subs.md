# 한글 텍스트·자막 처리 (한국화의 핵심 파일)

이 파일이 이 스킬이 원본과 갈리는 가장 큰 지점이다. Phase 3(프롬프트 작성)과
Phase 6(조립) 전에 읽는다.

## 문제: 생성 모델은 한글을 못 그린다

이미지·영상 생성 모델은 라틴 문자도 자주 뭉개지만, **한글은 훨씬 심하다.**
자소(초성·중성·종성) 조합 구조 때문에 모델이 만들어내는 건 대개 한글처럼
생겼지만 존재하지 않는 글자다. 클립 안에 한글을 요구하면 결과는 셋 중 하나:

1. 존재하지 않는 자소 조합 (읽을 수 없음)
2. 한자·일본어 가나와 뒤섞인 형태
3. 아예 라틴 문자로 대체

셋 다 못 쓴다. 그러므로 **원칙은 하나다.**

> **클립 안에 한글을 넣지 않는다. 화면 위 한글은 전부 조립 이후 레이어로
> 얹는다.**

## 클립 안에서 텍스트가 필요할 때의 대체 수단

원본 스킬의 믹스드미디어 스타일은 어차피 모든 텍스트를 금지한다. 문제는
디오라마 스타일 — 소품 위 레터프레스 텍스트가 그 스타일의 시그니처다.
한국어판에서는 이렇게 우회한다:

| 원래 하려던 것 | 한국어판 대체 |
|---|---|
| 소품에 한글 라벨 ("만료", "누가 내나?") | **숫자·기호만** 소품에 인쇄. 한글 문구는 조립 레이어로 |
| 신문 1면 헤드라인 | 글자 없는 신문 조판 — 텍스트 자리를 **하프톤 블록·먹칠 바**로 |
| 문서·계약서 클로즈업 | 활자 대신 **추상 라인 패턴**, 도장·스탬프 형태만 |
| 간판·현판 | 글자 없는 형태만. 또는 로고 실루엣 없는 기하 도형 |
| 연도·금액 강조 | **아라비아 숫자만** 인쇄 (`1953`, `15`) — 숫자는 비교적 안정적으로 렌더된다 |

숫자는 한글보다 성공률이 높지만 그래도 완벽하지 않다. **중요한 숫자는 클립에
맡기지 말고 조립 레이어에서 얹는다.**

### 프롬프트에 넣을 네거티브 (한국어판 고정)

모든 블록 프롬프트의 NEGATIVE 줄에 아래를 그대로 넣는다:

```
NEGATIVE: readable text, letters, words, numbers, Korean characters, Hangul,
Chinese characters, Japanese kana, garbled lettering, captions, subtitles,
watermark, logo, signage, storefront signs, document text, newspaper headlines,
photorealism, live-action footage, 3D render, lip-sync, talking characters,
color drift.
```

디오라마 스타일에서 숫자 하나를 의도적으로 넣을 때만 예외를 판다:

```
No text anywhere except the numerals "1953". No Korean characters, no Hangul,
no gibberish letters, no captions, no watermark.
```

## 하단 세이프존

편집 단계에서 자막을 얹기 때문에 **화면 하단을 비워둔다.**

| 화면비 | 해상도 | 비워둘 영역 |
|---|---|---|
| 16:9 | 1920×1080 | 하단 180px (y ≥ 900) |
| 16:9 | 1280×720 | 하단 120px (y ≥ 600) |
| 9:16 | 1080×1920 | 하단 320px (y ≥ 1600) |

대략 **하단 17%**로 기억하면 된다.

프롬프트 SCENE 줄에 이렇게 명시한다:

```
Composition: keep the lower ~17% of the frame visually quiet — background
texture only, no key subject, no annotation strokes, no chart elements in
that band.
```

세이프존을 지키면 자막을 얹어도 핵심 요소를 가리지 않는다. 이걸 안 지키면
편집에서 크롭하거나 자막을 위로 올려야 하는데, 둘 다 결과가 나빠진다.

## 자막 굽기

### 1단계 — 서버 자막 가능 여부 확인

`explainer_video`의 `subtitles.font`에 한글 지원 폰트가 있는지 먼저 확인한다.
기본값 `anton`은 **한글 글리프가 없다** — 그대로 쓰면 두부(□□□)나 예측 불가
폴백이 나온다.

- 한글 지원 폰트(Noto Sans KR, Pretendard 계열 등)가 목록에 있으면 그걸로
  서버 자막을 켠다. 완료 후 반드시 실제 프레임을 눈으로 확인한다.
- 없거나 확실치 않으면 → **서버 자막을 끄고 2단계로.**

### 2단계 — 로컬에서 굽기 (기본 경로)

`explainer_video` 호출에서 `subtitles` 파라미터를 아예 생략해 무자막 MP4를
받는다. 그다음 로컬에서 자막을 얹는다.

**SRT 만들기.** 블록은 고정 10초 창이므로 타이밍이 이미 결정돼 있다.
블록 N의 자막 구간은 `(N-1)×10s ~ N×10s`. 다만 실제 보이스 테이크가 10초보다
짧으면 조립기가 가운데 정렬하므로, 정확히 맞추려면 각 테이크의 `durationSec`을
읽어 시작 오프셋을 계산한다:

```
블록 N 시작 = (N-1)×10 + (10 - durationSec_N) / 2
블록 N 끝   = 블록 N 시작 + durationSec_N
```

**자막 스타일 규칙 (이 채널 컨벤션):**

- **SRT 큐 1개 = 화면 1줄.** 두 줄로 흐르면 큐를 쪼갠다.
- 흰 글자, 회색 반투명 펠릿(둥근 배경) 위.
- 화면 맨 아래에 붙이지 말고 **바닥에서 띄운다** (세이프존 안쪽 위치).
- 나레이션 문장을 그대로 받아쓴다 (자막은 받아쓰기 레이어다).
- 클립 안 그래픽 텍스트와는 역할이 다르다 — 그래픽은 키워드·숫자만, 자막은
  문장 전체.

**굽는 방법 두 가지:**

- **ffmpeg** — 빠른 경로. 한글 지원 폰트를 명시해야 한다.
  ```
  ffmpeg -i input.mp4 -vf "subtitles=subs.srt:force_style='FontName=Pretendard,FontSize=42,PrimaryColour=&HFFFFFF&,BackColour=&H80303030&,BorderStyle=4,MarginV=120'" -c:a copy out.mp4
  ```
  `FontName`은 시스템에 실제 설치된 한글 폰트여야 한다. `fc-list :lang=ko`로
  확인.

- **Remotion** — 이 저장소가 Remotion 프로젝트라면 이쪽이 낫다. 자막 컴포넌트로
  펠릿 스타일·세이프존·줄바꿈을 정확히 제어할 수 있고, 생성 클립을 풀블리드
  배경으로 깔고 그 위에 정보 그래픽 템플릿을 얹는 것도 같은 타임라인에서 된다.

## 클립 위 한글 그래픽 얹기 (선택)

키워드·숫자 강조가 필요한 블록은 조립 후 레이어로 얹는다. 규칙:

- **나레이션 문장을 그대로 화면에 띄우지 않는다.** 그건 자막이 하는 일이다.
  화면 그래픽은 **키워드나 숫자만** — `15조원`, `1953년`, `40%`.
- 자막과 세로로 겹치지 않게 배치한다(자막은 하단, 그래픽은 상단/중앙).
- 배치가 대본에 없는 서열·인과를 만들지 않게 주의한다. 높이·중심·순서가
  주장을 암시한다.
- 흰 화면에 텍스트만 있는 장면을 연속으로 쌓지 않는다 — PPT처럼 읽힌다.
  생성 클립을 배경으로 깔고 얇은 타이포를 얹는 편이 낫다.

## 검수 체크리스트 (조립 후 필수)

최종 MP4를 넘기기 전에 실제로 확인한다:

- [ ] 클립 안에 깨진 글자가 보이는 프레임이 있는가 → 있으면 그 블록 재생성
- [ ] 자막이 두부(□□□)로 나오는가 → 폰트 문제, 로컬 경로로 전환
- [ ] 자막이 화면 요소를 가리는가 → 세이프존 위반, 해당 블록 재생성 또는
      자막 위치 조정
- [ ] 자막 타이밍이 음성과 맞는가 → 특히 짧은 테이크의 가운데 정렬 보정
- [ ] 자막 한 큐가 두 줄로 흐르는가 → 큐 분할
