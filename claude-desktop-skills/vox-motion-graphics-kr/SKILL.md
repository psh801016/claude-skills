# 한국어 Vox 스타일 모션그래픽 익스플레이너 (힉스필드 MCP)

> **★ 2026-08-25 — Higgsfield 사용 불가.** 아래 본문이 Higgsfield(Nano Banana Pro)를 주 생성 도구로 적고 있으나 사용자 지시로 웹 UI·MCP 어느 경로도 쓰지 않는다(`rules.md` Higgsfield 절이 정본). **생성 도구만 다른 경로로 바꾸고 프롬프트 설계·레이어 분리·QC 절차는 그대로 따른다.** 생성 경로가 정해져 있지 않으면 사용자에게 어디서 뽑을지 먼저 확인한다.

주제 하나 — 혹은 아무것도 없이 — 완성된 한국어 해설 영상 한 편까지. 볼드한
에디토리얼 콜라주 비주얼, 다큐 나레이터, 사실 기반의 촘촘한 대본, 최종 MP4
하나. 힉스필드 MCP의 `video-explainer` 워크플로우 위에서 돌아간다.

**Vox 룩 한 줄 요약:** 종이 질감 위를 떠다니는 아카이브 사진 컷아웃, 플랫한
컬러 필드, 하프톤 액센트, 손으로 그린 동그라미와 밑줄, 추상적으로 자라나는
차트와 지도, 스냅한 카메라 푸시 — 촬영된 장면이 아니라 **움직이는 잡지
지면**이다.

## ⚠️ 이 스킬의 대전제 — 언어 분리 원칙

한국어화에서 가장 많이 깨지는 지점이다. 반드시 지킨다.

| 레이어 | 언어 | 이유 |
|---|---|---|
| 생성 모델에 보내는 프롬프트 | **영어** | 이미지·영상 모델은 영어 프롬프트 이해도가 압도적으로 높다. 한국어 프롬프트는 스타일 준수율이 떨어진다 |
| 나레이션 대본 | **한국어** | TTS 입력 |
| 자막 | **한국어** | 별도 레이어 |
| 클립 안에 렌더링되는 글자 | **한글 금지** (아래 참조) | 생성 모델이 한글을 못 그린다 |

**한글은 클립 안에 절대 넣지 않는다.** 이미지·영상 생성 모델은 한글 자소를
제대로 렌더링하지 못한다 — 라틴 문자보다 훨씬 심하게 깨진 글자가 나온다.
화면 안 한글이 필요하면 조립 단계에서 얹는다. 자세한 건
`references/korean-text-subs.md`를 Phase 3 전에 읽을 것.

## 작동 방식

이 스킬은 **손 안 대고 끝까지** 돌아가도록 만들어졌다. 사용자는 주제 발굴,
대본, 목소리, 에셋, 조립을 전부 위임한 상태다.

- 사용자가 주제·앵글·길이·목소리를 지정했으면 그대로 따른다. 지정 안 한 건
  아래 기본값으로 스스로 정한다.
- 첫 **유료** 생성 직전에 짧은 계획 메시지를 한 번 띄운다(주제, 앵글, 블록
  수, 화면비, 보이스, 예상 크레딧). 그리고 **승인을 기다리지 말고 바로
  진행**한다. 사용자가 상의해달라고 한 경우만 대기.
- 기본값으로 답할 수 있는 질문 때문에 파이프라인을 중간에 세우지 않는다.
  조립 안 된 낱개 클립만 던지고 끝내는 건 실패다.

기저 힉스필드 `video-explainer` 워크플로우는 스타일과 보이스를 대화형으로
물어본다. 이 스킬은 그 질문들을 미리 답해둔다(믹스드미디어 프리셋, 한국어
다큐 보이스 자동 선택). 사용자가 직접 고르겠다고 할 때만 갤러리·보이스
피커를 띄운다.

## 기본값

| 설정 | 기본값 | 바꿀 때 |
|---|---|---|
| 화면비 | **16:9 가로** — 국내 유튜브 롱폼 기준. 모든 클립에 `aspect_ratio: "16:9"` 명시 (스타일 키만으로는 프레이밍이 안 잡힌다 — 검증됨) | 숏폼/릴스 요청 → `9:16` |
| 스타일 | 믹스드미디어. 16:9는 자체 스타일 키 생성 필요(이미지 1장 비용), 9:16은 프리셋 id `80e4dd7b-cd65-42d4-b191-b58d62558602` 무료 | 사용자가 다른 프리셋 지정 또는 레퍼런스 이미지 제공 |
| 길이 | 1분 → 6블록 (N = 분 × 6, 블록당 10초 클립 1개) | 사용자가 길이 지정 (1~10분) |
| 캐릭터 | 얼굴 없음(페이스리스) | 사용자가 호스트/마스코트 요청 |
| 나레이션 | **한국어**, ~습니다체 | 사용자 지정 |
| 보이스 | `list_voices`에서 한국어 지원 보이스 중 낮고 차분한 다큐 톤 자동 선택. **사용자 클론 보이스가 있으면 그걸 최우선** | 사용자가 직접 고르겠다 → 피커 띄우고 대기 |
| 자막 | **서버 자막 끄고 로컬에서 굽는다** (기본 폰트 `anton`은 한글 미지원 — 두부현상). `references/korean-text-subs.md` 참조 | 한글 지원 폰트가 확인되면 서버 자막 사용 가능 |
| 세이프존 | **하단 180px(1080 기준, y≥900) 비움** — 편집자 자막 오버레이 자리 | 사용자가 필요없다고 하면 해제 |

## 스토리 엔진 (그냥 예쁜 영상과 터지는 영상의 차이)

예쁘지만 서로 무관한 장면들의 나열은 박물관 슬라이드쇼로 읽힌다. 레퍼런스급
영상이 먹히는 이유:

- **관통하는 오브젝트 하나.** 물리적 은유 하나가 **모든** 블록을 통과하며
  고조된다(모든 장면을 가로지르는 타들어가는 도화선, 바늘을 향해 부풀어가는
  풍선). 시청자가 러닝타임 내내 붙잡는 물건이고, 피날레가 값을 치른다. 블록을
  쓰기 전에 이 오브젝트부터 설계한다.
- **질문 훅, 마지막에 답.** 질문을 소품 위에 얹고("누가 내나?", "누가 먼저
  깜빡이나?") 블록 1이나 피날레에 배치. 나레이션은 킬러 라인까지 답을 아낀다.
  ※ 한글 텍스트를 소품에 얹는 건 금지 — 조립 단계 오버레이로 처리.
- **페이크 원테이크.** 모든 클립을 하나의 연속 FPV 카메라 무브로 쓴다. 시작과
  끝을 완전한 모션블러 상태로(다이브, 휩, 플레어, 낙하) — 그러면 블록 사이
  하드컷이 끊기지 않은 한 샷처럼 읽힌다. 병렬 생성 가능, 프레임 매칭 불필요.
- **3초마다 임팩트 하나**(슬램, 스탬프, 충격파, 스냅), 블록당 최소 한 번
  속도 램프(슬로모 비트 → 휩). 극단적 매크로와 와이드 디오라마를 번갈아 —
  스케일로 후려친다(거대한 얼굴 → 개미만한 인물 → 거대한 소품).
- **기억되는 리빌 샷 하나.** 군중이 의미 있는 실루엣으로 배열된다든가,
  카메라가 크레인업할 때만 보이는 리빌.

## 파이프라인

| 페이즈 | 하는 일 | 도구 |
|---|---|---|
| T 주제 | 받은 주제 사용, 또는 국내 트렌드에서 발굴 | WebSearch / WebFetch (+ `insane-search` 스킬) |
| R 리서치 | 검증된 사실·숫자·이름 수집, 출처 목록 유지 | WebSearch / WebFetch |
| 1 스타일 키 | 스타일 레퍼런스 미디어 확보 | `resolve_explainer_preset` (9:16) / `generate_image` (16:9) |
| 2 대본 | 한국어 나레이션 N블록 | 추론 (무료) |
| 3 블록 프롬프트 | 영어 영상 프롬프트 N개 | 추론 (무료) — 템플릿 `references/vox-prompts-kr.md` |
| 4 클립 | 10초 클립 N개, 모든 클립에 스타일 키 부착 | `generate_video` |
| 5 보이스 | 한국어 나레이터 1명, N테이크, 동일 voice_id | `list_voices` + `generate_audio` |
| 6 조립 | 클립 + 테이크 → MP4 1개, 한글 자막 처리 | `explainer_video` (+ 로컬 자막) |

Phase 1 전에 `references/vox-prompts-kr.md`, Phase 3 전에
`references/korean-text-subs.md`를 읽는다. T·R·2·3은 무료, 1(16:9
브랜치)·4·5는 크레딧 소모.

**잡 모델:** 모든 `generate_*` 호출은 비동기 잡을 제출하고 잡 id를 돌려준다.
`job_status { jobId, sync: true }`로 폴링하거나, 툴 결과/알림 스트림 또는
`show_generations`로 완료를 확인한다. 완료된 잡 id는 이후 생성의
`medias[].value`로, Phase 6의 `video`/`audio`로 그대로 쓴다 — 원본 URL이
필요한 경우는 거의 없다. Phase 4 전에 `generate_video` 한 건에
`get_cost: true`를 붙여 총 예상 비용을 계산하고 계획 메시지에 넣는다.

## Phase T — 주제

**주제를 받았으면** → 그대로 쓰고 Phase R로.

**주제가 없으면** → 지금 국내에서 반응 있는 주제를 찾는다:

1. 한국 소스 우선으로 검색한다:
   - 구글 트렌드 한국 / 네이버 데이터랩 급상승 검색어
   - 유튜브 인기 급상승 (한국)
   - 커뮤니티·뉴스레터 화제 (요즘IT, 긱뉴스 등 IT/비즈니스 이슈)
   - 글로벌 이슈라면 "이게 한국에 어떻게 닿는가" 각도를 반드시 붙인다
   - 차단 사이트(네이버 블로그, 디시, 에펨코리아 등)는 `insane-search`
     스킬로 우회
2. 좋은 주제의 조건: 핵심에 **"왜/어떻게" 질문**이 있고, **놀라운 숫자나
   반전**이 최소 하나, 강한 **시각적 잠재력**(지도, 차트, 물건, 아카이브
   이미지), 그리고 넓은 소구력. "왜 X가 갑자기 다 보일까", "X가 그렇게 비싼
   진짜 이유", "X가 조용히 Y를 바꾼 방법" 이 형태를 노린다.
3. 피할 것: 진행 중인 참사·재난, 데이터 각도 없는 연예 가십, 독립된 두 출처로
   검증 안 되는 것. **실존 정치인·공인 실명 비방**과 특정 기업 저격도 피한다.
4. 가장 센 후보를 스스로 고르고 계획 메시지에 적는다(사용자가 바꿀 경우를
   대비해 차선 하나 함께).

## Phase R — 리서치

기억에 의존해 대본을 쓰지 않는다. 고른 주제를 검색하고 상위 2~3개 출처를
읽어서 수집한다: 훅이 될 통계, 구체적 사실·숫자·날짜 3~5개, 반직관적 전환점,
블록을 생생하게 만들 인물·장소·사건 디테일. 모든 숫자를 두 번째 출처로
교차 검증한다. 짧은 **출처** 목록을 유지하고 최종 전달 메시지에 포함한다.
지어낸 인용, 지어낸 숫자 금지 — 애매하지만 사실인 문장이 구체적이지만 거짓인
문장보다 낫다.

**숫자는 한국 기준으로 번역한다.** 이건 선택이 아니라 의무다:

- 외화·외국 단위 → 원화·한국 단위 환산. `110억 달러` → `약 15조원`
  (환산 시점 환율 명시). `50만 달러` → `약 7억원`.
- 큰 숫자는 체감 기준을 붙인다. `15조원` 단독은 뇌가 멈춘다 →
  `15조원. 한 해 국내 영화 시장 전체 규모의 몇 배입니다` 식으로 아는 것 위에
  얹는다.
- 의미를 못 붙이는 숫자는 차라리 뺀다.
- 환산·비교에 쓴 기준값도 출처 목록에 넣는다.

## Phase 1 — 스타일 키

**16:9 (기본):** 프리셋 키는 세로 프레이밍을 강제하므로, `generate_image`로
가로 스타일 키를 직접 만든다. 모델 `nano_banana_pro`, `aspect_ratio: "16:9"`,
프롬프트는 `references/vox-prompts-kr.md`의 STYLE KEY 프롬프트. 완료까지
폴링하고, 그 잡 id가 스타일 키가 된다. (이미지 생성 1건 비용)

**9:16 요청 시:** `resolve_explainer_preset`에 프리셋 id
`80e4dd7b-cd65-42d4-b191-b58d62558602`(믹스드미디어)를 넘긴다. 반환된
`media_id`가 곧 스타일 키다 — Phase 4의 **모든** 클립에
`medias: [{ value: <media_id>, role: "image" }]`로 붙인다. 이 경로는 무료다.

## Phase 2 — 대본 (한국어)

`Block 1 … Block N` 라벨로 N개 블록, 10초 클립당 하나. 낭독 텍스트만 —
지문·괄호 설명 금지.

### 분량 기준 (한국어)

**블록당 40~50 음절**(대략 13~17 어절)로 시작한다. 한국어 다큐 나레이션은
초당 약 5음절, 즉 9초 ≈ 45음절이 대략의 감이다. 다만 **TTS 실측 없이는
믿지 않는다** — 이 값은 첫 블록을 실제로 뽑아서 `durationSec`을 보고 보정할
출발점일 뿐이다. 첫 테이크가 나오면 실제 음절/초를 계산해서 나머지 블록
길이를 조정한다.

한국어 TTS 페이싱 주의:
- 마침표마다 쉬는 구간이 길다. 짧은 문장을 여러 개 붙이면 같은 음절 수라도
  훨씬 길어진다. **쉼표로 이어진 한 문장**이 가장 예측 가능하다.
- 숫자·영문 약어는 읽는 방식이 갈린다. 애매한 건 읽는 대로 적는다:
  `40%` → `사십 퍼센트`, `2026년` → 보통 괜찮지만 불안하면 `이천이십육 년`,
  `MCP` → `엠시피`.
- 외래어·영문 고유명사는 한글 표기로 적는다: `Higgsfield` → `힉스필드`.

### 구조 (Vox 공식)

- **블록 1 — 콜드 오픈.** 가장 놀라운 사실이나 질문을 담백하게. 인사말 없고
  "오늘은 ~에 대해 알아보겠습니다" 같은 예고 없음.
- **블록 2 — 판돈.** 이게 왜 이상한지, 시청자한테 왜 중요한지.
- **중간 블록들 — 근거.** 블록당 아이디어 하나, 각각 Phase R에서 나온 구체적
  숫자·날짜·장소·비교에 못 박는다. 점점 고조.
- **블록 N−1 — 전환.** 반직관적 리빌, "그런데 진짜는 따로 있습니다".
- **블록 N — 해소 + 킬러.** 답을 착지시키고, 첫 문장을 다시 정의하는 한 줄로
  끝낸다.

### 톤

호기심 있고 정확하고 살짝 건조하게. 짧은 평서문. 해설자는 설명하지, 띄우지
않는다.

- 어미는 `~습니다` 기본. `~죠`, `~거든요`를 리듬 전환용으로 섞되 과하지 않게.
- 금지: "놀랍게도", "역설적이게도", "결론적으로" 같은 진행자 톤 부사.
  "~라고 할 수 있습니다" 식 맥없는 마무리.
- 번역투 금지. "~에 대한 것입니다", "~를 가지고 있습니다" 대신 자연스러운
  한국어로.

**사용자가 머니스웨거 채널용이라고 하면** `moneyswagger-script` 스킬의 말투
규칙을 따른다(흐르는 구어체 문단, 1인칭 실행 서사, 끊어치기·아포리즘 금지).
이 경우 블록 분할은 대본을 먼저 쓴 뒤 10초 단위로 자른다.

## Phase 3 — 블록 프롬프트

블록마다 영상 프롬프트 하나씩 **영어로** 쓴다. 각 프롬프트는 해당 블록의
나레이션을 Vox 콜라주 언어로 시각 번역한 것이다. `references/vox-prompts-kr.md`의
라벨 템플릿과 장면 어휘를 그대로 쓴다. 잊기 쉬운 규칙 넷:

- **클립 안에 읽히는 글자를 넣지 않는다.** 특히 **한글은 절대 금지** — 생성
  모델이 한글 자소를 뭉갠다. 타이포 비트는 추상적인 하이라이트 바, 검열 블록,
  동그라미, 밑줄로 표현한다. 실제 자막은 조립 단계에서 얹는다.
- **화면 안에서 아무도 말하지 않는다.** `AUDIO:` 줄은 앰비언스·SFX·음악만.
  나레이션은 조립 때 블록별로 붙는다.
- **하단 세이프존을 비운다.** 프롬프트에 핵심 요소를 화면 하단 약 17%(1080
  기준 하단 180px) 밖으로 배치하도록 명시한다. 자막이 들어갈 자리다.
- **한국 소재를 쓸 때 주의.** 한글 간판·현판이 들어간 장면은 글자가 깨진다.
  한국적 소재는 글자 없는 요소로(기와지붕, 태극 문양이 아닌 추상 도형, 지도
  실루엣) 표현한다.

## Phase 4 — 클립

**엔진 선택:**

- `gemini_omni` — 클립당 30크레딧, 빠름, 믹스드미디어 콜라주의 주력. 묘사만으로
  알아볼 수 있는 정치인 얼굴을 렌더링하는 유일한 엔진이기도 하다
  (`references/diorama-doc-kr.md`의 모더레이션 맵 참조).
- `seedance_2_0` — 45크레딧(720p std) / 90크레딧(1080p), 레퍼런스급 시네마틱:
  프롬프트 안의 컷 전환("Shot 1 … Cut to shot 2")을 실행하고, 진짜 속도 램프와
  FPV 무브를 하고, 나레이션 아래에서도 살아남는 네이티브 SFX 사운드
  디자인(`generate_audio: true`)을 낸다. 디오라마 스타일과 "임팩트 있게"
  브리프의 기본값. 호출 템플릿은 `references/diorama-doc-kr.md`.

`generate_video` 잡 N개 제출 — **모든 잡에 스타일 키를 붙인다**(재사용 소품이
있으면 추가 `image_references`로 함께):

```
generate_video
  model: "gemini_omni"
  prompt: <블록 N 영상 프롬프트, 영어>
  duration: 10
  resolution: "720p"
  aspect_ratio: "16:9"
  medias: [ { value: "<스타일 키 media_id 또는 잡 id>", role: "image" } ]
```

`aspect_ratio`를 **반드시 명시**한다 — 기저 워크플로우 설명과 달리 키 이미지가
프레이밍을 안정적으로 정하지 못한다. 9:16 키로 돌렸는데 16:9 클립이 나온 실제
사례가 있다.

서버가 첫 제출을 `preset_recommendation` 알림으로 가로챌 수 있다(콜라주
프롬프트를 자기네 "3D RENDER" 프리셋에 패턴 매칭한다). 알림의
`retry_literal_with`에 있는 `declined_preset_id`를 넣어 재제출해 거절한다 —
포토리얼/3D 프리셋은 절대 수락하지 않는다.

배치로 제출하고, 모든 잡 id를 블록 번호와 매칭해 기록하고, 실패한 블록만
재제출한다. 클립이 실사/포토리얼로 나오면 STYLE과 NEGATIVE 줄을 강화해서 그
블록만 다시 돌린다 — 같은 실패가 두 번 나오면 시드가 아니라 프롬프트가 잘못된
것이다. `gemini_omni`가 거부되면 `models_explore(type: 'video')`로 현재 영상
모델 id를 확인한다. 절대 조용히 포토리얼 모델로 갈아타지 않는다.

## Phase 5 — 보이스오버 (한국어)

1. `list_voices`를 호출한다. **한국어를 지원하는** 보이스 중 낮고 차분한 다큐
   나레이터를 고른다(광고 읽는 톤 말고 침착한 권위). 정확한 `voice_id`와
   `voice_type`을 기록한다.
   - **사용자가 클론한 본인 보이스가 목록에 있으면 그걸 최우선**으로 쓴다.
   - 한국어 보이스가 하나도 없으면 파이프라인을 세우고 사용자에게 알린 뒤
     선택지를 준다: (a) 영어 나레이션 + 한글 자막 (b) 대본만 넘기고 로컬 TTS.
     임의로 영어로 진행하지 않는다.
   - 사용자가 직접 고르겠다고 한 경우만 피커를 띄우고 대기.

2. 블록당 `generate_audio` 한 번, 매번 같은 보이스로:

```
generate_audio
  model: "seed_audio"
  voice_type: "<preset|element>"
  voice_id: "<list_voices에서>"
  prompt: "<블록 N 문장, 한국어 평문>"
```

길이가 안 맞을 때 손잡이: `speech_rate`(-50..100)를 한 단계 올리거나, 문장을
줄여서 다시 뽑는다. 각 테이크의 잡 id를 블록에 매칭해 기록한다.

**조립 전에 모든 테이크의 실제 길이를 확인한다** — 완료된 잡에서
`durationSec`을 읽고(`show_generations`) 테이크당 **9.0~10.5초**를 목표로 한다.
조립기는 짧은 테이크를 가운데 정렬하고(7초 테이크는 1.5초 늦게 시작 — 싱크가
안 맞아 보인다) 긴 테이크는 속도 압축한다(13초 테이크는 30% 압축 — 급하게
들린다).

한국어 TTS는 페이싱 편차가 특히 크다. 마침표마다 쉬는 시간이 붙어서, 같은
음절 수라도 짧은 문장 여러 개는 쉼표로 이은 한 문장보다 3~4초 길어질 수 있다.
**한 호흡으로 이어지는 문장을 선호하고**, 1~2회 재녹음 라운드를 예상하고,
블록당 가장 좋은 테이크를 남긴다. 살짝 넘치는 게 늦게 시작하는 것보다 낫다.

## Phase 6 — 조립 (자동, 필수)

모든 클립과 테이크가 끝나는 즉시, 같은 실행 안에서, 요청받지 않아도 조립한다.

조립 전에 완성된 클립의 실제 `width`/`height`를 잡 레코드에서 읽고 **그 값을**
넘긴다 — 클립이 계획과 다른 화면비로 렌더됐으면 조립은 계획이 아니라 클립을
따라야 한다.

### 한글 자막 처리 (한국화 핵심)

서버 자막의 기본 폰트 `anton`은 **한글 글리프가 없다**. 그대로 쓰면 두부
현상(□□□)이나 엉뚱한 폴백 폰트가 나온다.

**절차:**

1. 조립 전에 자막 폰트 옵션에 한글 지원 폰트가 있는지 확인한다.
2. 있으면 그 폰트로 서버 자막을 켠다.
3. **없으면 서버 자막을 끄고**(`subtitles` 파라미터 생략) 영상만 조립한 뒤,
   자막은 로컬에서 굽는다. 방법과 스타일 규칙은
   `references/korean-text-subs.md` 참조. 이게 기본 경로다.

```
explainer_video
  params:
    width: 1280           # 16:9 — 항상 클립의 실제 크기
    height: 720           # 9:16이면 720 x 1280
    # subtitles: 한글 폰트 확인 전까지 생략
    items:
      - { video: "<클립 1 잡 id>", audio: "<보이스 1 잡 id>" }
      …
      - { video: "<클립 N 잡 id>", audio: "<보이스 N 잡 id>" }
```

블록은 고정 10초 창이다: 짧은 테이크는 가운데 정렬, 살짝 넘치는 건 피치 보존
스피드업, 영상은 절대 늘리지 않는다 — 총 길이 = N × 10초 정확히. 반환된 잡을
완료까지 폴링한 뒤 `job_display`로 최종 MP4를 보여준다.

## 전달

최종 메시지에 담을 것: 영상, 주제와 앵글 한 문장, **전체 한국어 대본**(사용자가
재사용할 수 있게), **출처 목록**, 그리고 숫자 환산에 쓴 기준(환율·시점).

그다음 — 시키지 않은 채로 실행하지 말고 — 제안만 한다:
- 유튜브 업로드용이면 제목·설명·태그
- 숏폼/캐러셀/스레드 OSMU 팩
- Remotion 프로젝트로 가져가서 정보 비트 템플릿을 얹을지

## 실패 대응

- 클립이 스타일에서 이탈 → 키를 다시 붙이고 STYLE/NEGATIVE를 조인 뒤 그 블록만
  재실행.
- 보이스 테이크가 10.5초 초과 → 문장을 줄이거나 `speech_rate`를 올려 그 블록만
  재녹음.
- `voice_id`/`voice_type` 오류 → `list_voices`를 건너뛴 것. 호출해서 정확한
  쌍 하나를 모든 곳에 재사용.
- 조립이 id를 거부 → 그 잡이 아직 종료 상태가 아니다. 폴링한 뒤 N개 아이템
  전부를 순서대로 넣어 재시도. 블록 N의 오디오는 항상 클립 N에 붙는다.
- 영상 잡이 에러 텍스트 없이 `failed`/`nsfw` → 운이 아니라 모더레이션이다.
  `references/diorama-doc-kr.md`의 모더레이션 맵 확인.
- 클립에 깨진 글자가 보임 → 프롬프트 어딘가에 텍스트를 유도하는 단어가 있다.
  NEGATIVE를 강화하고 SCENE에서 간판·문서·표지판 묘사를 뺀 뒤 재실행.
- 사용자가 개별 산출물을 원함(SFX만, 클립 낱개, 스틸) → 원본 클립에는 목소리가
  없다. 나레이션은 조립본에만 존재하므로, 로컬에서 클립별 오디오/프레임을
  추출하면(AVFoundation/ffmpeg) 깨끗한 무음 에셋을 얻는다.

## 브랜드 안전 (광고·협찬 영상일 때)

협찬 영상이면 시작 전에 확인한다:

- 서드파티 로고·브랜드명·저작권 푸티지를 **화면에** 넣지 않는다. 음성 언급은
  별개 문제이므로 브리프 조항을 확인할 것.
- 실존 공인 얼굴 금지. 필요하면 검열바·하프톤 처리.
- 캐릭터는 가상 인물로.
- 협찬 사실은 대본 초반에 밝힌다.
